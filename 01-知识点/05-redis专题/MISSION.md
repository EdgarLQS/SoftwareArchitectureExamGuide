# Mission: Redis 与系统架构设计师考试

## Why

从零建立 Redis 的运行模型和架构判断能力，把缓存、持久化、高可用、分布式锁和高并发设计真正用到系统架构设计师的综合知识、案例分析和论文中。

## Success looks like

- 能根据业务约束选择 Redis 数据类型、缓存模式和高可用方案。
- 能用实验或流程图解释缓存一致性、故障转移、锁安全释放和防超卖。
- 能在原题和变式案例中写出有机制、有取舍、有故障处理的架构答案。
- 能把 Redis 方案迁移成高并发、微服务、云原生和性能优化论文段落。

## Constraints

- 以 Markdown 课程、命令实验、案例训练和错题回归为主。
- 先理解机制，再记命令和考点；版本相关内容必须标注来源与版本。
- 每次学习留下可复查的实验结果或答题记录，不把“看过”当成“掌握”。

## Out of scope

- 暂不深入 Redis Enterprise 商业特性、源码阅读和生产集群运维自动化。
- 暂不把 Redis 之外的数据库、消息队列和云产品扩展成独立课程。
