# 05 RAG、向量数据库与知识图谱协同

## 一、RAG 流程

RAG（检索增强生成）先从外部知识中检索相关上下文，再交给生成模型回答，以减少模型只依赖参数记忆带来的问题。

```text
文档采集
  → 文档切分
  → Embedding 向量化
  → 向量数据库建立索引
  → 根据问题召回相关片段
  → 拼接提示词
  → 大模型生成答案
  → 结果校验、引用和审计
```

## 二、向量数据库的作用

- 保存文档、图片或其他对象的嵌入向量及其元数据。
- 根据相似度进行近似最近邻检索，召回语义相关内容。
- 通过过滤条件、索引和分片支持大规模检索。
- 通常与原文存储、权限系统和文档版本系统配合使用。

不要把向量数据库等同于大模型：向量数据库负责存储和检索，大模型负责理解上下文并生成结果。

## 三、RAG 与知识图谱的关系

| 维度 | RAG | 知识图谱 |
|---|---|---|
| 核心对象 | 文档片段和语义向量 | 实体、关系、属性和结构 |
| 核心能力 | 语义检索和上下文增强 | 结构化查询和关系推理 |
| 优势 | 接入非结构化文档较灵活 | 关系明确、可解释性较好 |
| 局限 | 召回和生成可能不稳定 | 构建、维护和更新成本较高 |

两者可以组合：

```text
向量数据库负责语义相似检索
知识图谱负责实体关系约束和结构化推理
大模型负责理解上下文、组织答案和生成表达
```

知识图谱的七阶段、RDF、OWL、图数据库和推理内容统一学习[现有知识图谱专题](../04-知识图谱/)，本文件只保留与 RAG 的连接关系。

## 四、RAG 架构风险与措施

| 风险 | 可能原因 | 措施 |
|---|---|---|
| 召回不相关 | 切分不合理、向量质量差 | 优化切分、Embedding 和检索参数 |
| 召回不完整 | 只使用单一检索方式 | 关键词、向量和结构化条件组合检索 |
| 答案幻觉 | 上下文不足或模型过度生成 | 要求引用、拒答、结果校验和人工审核 |
| 数据过期 | 文档更新未同步索引 | 版本、时间戳和增量更新 |
| 权限泄露 | 检索未带用户权限 | 文档级权限过滤和审计 |

## 五、RAG 架构答题模板

```text
系统先对文档进行切分和向量化，写入向量数据库；
用户提问后检索相关片段，与问题拼接为上下文交给大模型生成；
再通过权限过滤、引用校验、版本更新和日志审计保证安全性、准确性和时效性。
```
