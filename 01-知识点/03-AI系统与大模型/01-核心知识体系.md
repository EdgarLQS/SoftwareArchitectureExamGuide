# 01 核心知识体系：先建立 AI 系统地图

## 一、最小术语集

| 术语 | 考试表达 |
|---|---|
| 人工智能 AI | 让系统表现出感知、理解、预测、决策或生成能力的技术集合 |
| 机器学习 ML | 从数据中学习规律，并用学习到的模型完成预测或决策 |
| 深度学习 DL | 使用多层神经网络学习数据表示和任务映射的方法 |
| 模型 | 对数据规律的参数化表示，用于训练后进行推理 |
| 参数 | 模型在训练中学习得到的数值，用来决定模型行为 |
| 训练 | 使用数据和目标函数调整模型参数，使模型学会任务规律 |
| 推理 | 使用已训练模型和输入数据生成预测、分类或生成结果 |
| 微调 | 在已有模型基础上，用特定领域或任务数据继续训练以适配目标场景 |
| 评估 | 用指标、测试集和运行约束判断模型效果和服务质量 |

最重要的边界：

```text
训练 = 学习参数
微调 = 基于已有模型适配任务
推理 = 使用已训练模型产生结果
评估 = 判断模型和服务是否满足要求
```

## 二、AI 系统主流程

```text
数据采集
  → 数据清洗与标注
  → 模型训练或微调
  → 模型评估
  → 模型压缩与优化
  → 模型部署
  → 推理服务
  → 监控、反馈与治理
```

| 环节 | 作用 | 典型输入 | 典型输出 | 主要风险或措施 |
|---|---|---|---|---|
| 数据采集 | 获取任务所需数据 | 日志、文本、图像、传感器数据 | 原始数据集 | 来源不可信，需授权和质量检查 |
| 清洗与标注 | 去噪、去重、统一格式并形成标签 | 原始数据 | 可训练数据集 | 噪声、偏差、泄露，需脱敏和抽检 |
| 训练或微调 | 学习通用或领域参数 | 数据集、已有模型 | 模型权重 | 过拟合、资源消耗，需验证集和资源调度 |
| 评估 | 判断模型效果和服务质量 | 模型、测试集、运行环境 | 指标与评估报告 | 只测准确率不测延迟、安全和资源 |
| 压缩优化 | 适配资源和性能约束 | 原始模型 | 优化模型 | 精度下降，需进行精度—性能权衡 |
| 部署 | 将模型放到目标运行环境 | 模型、运行时、硬件 | 可调用模型实例 | 环境不兼容，需版本和依赖管理 |
| 推理服务 | 接收请求并返回结果 | 请求、模型实例 | 预测或生成结果 | 延迟、并发、故障，需限流和弹性 |
| 监控治理 | 发现漂移、异常和风险并反馈 | 日志、指标、用户反馈 | 告警、版本迭代、审计记录 | 幻觉、偏差、隐私，需持续治理 |

## 三、四类案例答法

### 定义题

```text
X 是……，通过……处理……，解决……问题；在……约束下存在……限制。
```

### 架构题

```text
系统由……组成；数据按……流程流转；通过……保证性能、可靠性、安全性和可扩展性。
```

### 评估题

不要只写准确率，还要按题干选择：

- 效果：准确率、精确率、召回率、F1 等；
- 服务：响应延迟、吞吐量、并发数、可用性；
- 资源：显存、内存、CPU/GPU/NPU 使用率和能耗；
- 风险：安全性、隐私、偏差、幻觉、可解释性。

### 作答检查

- 是否先给结论？
- 是否说明作用对象和核心目标？
- 是否结合题干约束？
- 是否写出代价、限制或风险？
- 架构题是否写出组件和数据流？
