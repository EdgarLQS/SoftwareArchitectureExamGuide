# 02 数据、训练、评估与模型服务

## 一、数据准备

```text
数据源识别 → 采集 → 清洗 → 去重/脱敏 → 标注 → 训练/验证/测试划分
```

- 清洗解决格式不一致、重复、缺失、噪声和异常值问题。
- 标注为监督学习提供目标答案，也可用于评估和错误分析。
- 训练集用于学习参数，验证集用于选择模型和超参数，测试集用于最终检验。
- 数据要关注代表性、时效性、准确性、完整性、隐私和授权。

## 二、训练、微调与推理

| 概念 | 输入 | 主要动作 | 输出 | 不要混淆 |
|---|---|---|---|---|
| 训练 | 大规模数据和目标 | 从数据学习模型参数 | 通用或任务模型 | 不是调用模型回答问题 |
| 微调 | 已有模型和领域数据 | 继续调整部分或全部参数 | 更适合目标领域的模型 | 不等于推理 |
| 推理 | 输入数据和已训练模型 | 执行前向计算 | 预测、分类或生成结果 | 通常不改变模型参数 |
| 评估 | 模型、测试集和运行环境 | 计算效果与服务指标 | 评估报告 | 不能只看准确率 |

## 三、学习方式的最低限度区分

- **监督学习**：有标签数据，学习输入到目标输出的映射。
- **无监督学习**：没有明确标签，发现数据的结构、聚类或表示。
- **强化学习**：通过环境反馈和奖励信号学习行动策略。

案例中如果题目没有要求算法细节，优先写“数据—目标—训练—评估—部署”的系统链路。

## 四、模型服务化流程

```text
模型注册
  → 版本与依赖校验
  → 模型压缩/转换
  → 部署到推理运行时
  → API 或消息接口
  → 负载均衡与弹性伸缩
  → 日志、指标、链路和质量监控
  → 反馈、回滚或重新训练
```

服务设计要点：

1. 模型、代码、数据和运行时版本可追踪，出现问题能够回滚。
2. 根据并发和延迟要求选择同步或异步调用，并设置超时、限流和重试。
3. 将模型效果指标和系统服务指标分开监控。
4. 对输入、输出、模型版本和关键操作保留审计记录。
5. 通过灰度发布、A/B 对比或回滚降低新模型上线风险。

## 五、模型服务答题模板

```text
平台接收……数据，经……处理后调用……模型；
模型以……方式部署并通过……提供推理服务；
通过版本管理、资源调度、限流容错和监控反馈保证……。
```
