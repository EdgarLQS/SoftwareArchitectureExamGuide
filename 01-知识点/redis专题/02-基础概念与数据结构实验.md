
## 三、可复制实验

### 3.1 TTL 与缓存 Key

```bash
redis-cli SET study:user:1 "alice" EX 30
redis-cli GET study:user:1
redis-cli TTL study:user:1
```

回答：TTL 返回 `-1` 和 `-2` 分别表示什么？为什么缓存通常需要过期时间？

### 3.2 数据类型选择

```bash
redis-cli SET study:likes:article:1 0
redis-cli INCRBY study:likes:article:1 3

redis-cli HSET study:cart:user:1 sku:1001 2 sku:1002 1
redis-cli HINCRBY study:cart:user:1 sku:1001 1

redis-cli ZADD study:rank 98 alice 95 bob 99 carol
redis-cli ZREVRANGE study:rank 0 2 WITHSCORES
```

记录：每个 Key 选择了什么类型、业务操作是什么、为什么不用另一种类型。

### 3.3 集合和位图

```bash
redis-cli SADD study:team:a alice bob carol
redis-cli SADD study:team:b bob carol dave
redis-cli SINTER study:team:a study:team:b

redis-cli SETBIT study:sign:202608 0 1
redis-cli SETBIT study:sign:202608 1 1
redis-cli BITCOUNT study:sign:202608
```

回答：Set 解决了什么问题？Bitmap 为什么节省空间？Bitmap 的 offset 为什么不能直接当作任意业务 ID 而不评估空间跳跃？

## 四、扩展结构的考试边界

| 结构 | 适合问题 | 关键限制 |
|---|---|---|
| Bitmap | 大量布尔状态，如签到 | offset 稀疏时可能造成空间浪费 |
| HyperLogLog | 海量去重计数，如 UV | 近似值，不能取回成员 |
| Bloom Filter | 判断元素“可能存在/一定不存在” | 有假阳性，普通 Bloom Filter 不适合直接删除 |
| Geo | 经纬度附近查询 | 不是通用 GIS，精度和查询范围需评估 |
| Stream | 消息流、消费组、确认 | 需要单独理解积压、确认和重试 |
