# 软考案例与论文训练

> 目标：把 Redis 知识转成系统架构设计师三科可以直接使用的答案。

## 一、三科映射

| 科目 | 重点 | 输出形式 | 验收 |
|---|---|---|---|
| 综合知识 | 类型、命令、RDB/AOF、复制、淘汰、缓存问题 | 定义、判断、对比 | 选择题能排除相近干扰项 |
| 案例分析 | 缓存一致性、穿透/击穿/雪崩、锁、秒杀、高可用 | 流程图 + 分点答案 | 原题 ≥80%，变式题 ≥75% |
| 论文 | 高并发、微服务、云原生、性能优化中的缓存和锁 | 背景—方案—难点—指标—反思 | 方案有约束、指标和取舍 |

## 二、案例答题六步法

1. **识别问题**：是性能、可用性、一致性、容量还是安全问题？
2. **补充约束**：读写比例、峰值流量、可接受延迟、RPO/RTO、是否允许旧数据。
3. **画主链路**：客户端/网关 → 应用 → Redis → 数据库/MQ，并标出回源和故障路径。
4. **解释机制**：命令原子性、TTL、锁 token、复制偏移量、槽位或消息补偿。
5. **说明取舍**：一致性、性能、复杂度、成本和运维能力之间如何平衡。
6. **补齐兜底**：限流、降级、重试退避、幂等、监控、告警、恢复和数据校验。

## 三、训练题

### 题目 1：缓存一致性

商品读多写少，价格修改后要求秒级可见。请设计读写流程并说明缓存删除失败怎么办。

答题必须包含：Cache-Aside、先写数据库后删缓存、删除失败补偿、幂等、版本或时间戳、命中率和回源监控；不能只写“同步更新缓存”。

### 题目 2：热点商品击穿

热点商品每 5 分钟过期，过期瞬间大量请求访问数据库。比较互斥锁 + 物理过期与逻辑过期 + 异步刷新。

答题必须比较：数据新鲜度、请求是否阻塞、实现复杂度、内存占用、失败恢复和适用场景。

### 题目 3：秒杀防超卖

库存 10 万件，峰值请求远高于数据库承载能力。设计防超卖和订单最终落库方案。

答题必须包含：网关限流、Redis 预热、Lua 原子校验与扣减、MQ 削峰、幂等消费、数据库唯一约束、库存补偿和监控。

### 题目 4：Redis 主节点故障

说明主从复制、故障转移、持久化和客户端重连分别解决什么问题，并分析可能的数据丢失窗口。

答题不能把“Sentinel = 持久化”或“主从 = 强一致”作为结论，应明确异步复制和故障切换边界。

## 四、论文迁移模板

```text
在缓存层，我采用 Cache-Aside 模式，将热点数据放入 Redis，读请求优先访问缓存，未命中时回源数据库并设置带随机偏移的 TTL。
针对缓存穿透，采用参数校验、布隆过滤器和短 TTL 空值缓存；针对热点 Key 击穿，采用互斥刷新或逻辑过期；针对集中失效，采用分批预热、限流和高可用部署。
在一致性方面，业务写入先提交数据库，再删除缓存；删除失败通过消息补偿和幂等重试收敛，并通过命中率、回源 QPS、延迟和补偿积压监控效果。
```

这段模板必须替换成真实项目约束和真实指标，不能把示例数字直接当作项目事实。

## 五、错题回归规则

| 时间 | 动作 | 通过标准 |
|---|---|---|
| D0 | 当天写出错因、正确机制和一条反例 | 能不看答案复述 |
| D+2 | 重做原题并解释干扰项 | 原题正确 |
| D+7 | 做同考点变式题 | 变式题 ≥75% |
| D+21 | 混合案例限时作答 | 不重复同一错误，综合案例 ≥80% |

## 六、当前资料边界

历年题目可能存在图片缺失或整理稿不完整的情况。缺少原始题干时，训练题应标注“改编题”，不能把改编答案当作官方原题答案。
