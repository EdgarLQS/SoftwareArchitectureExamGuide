# Redis 速查卡

## 数据类型

| 类型 | 关键词 | 场景 |
|---|---|---|
| String | 值、计数、锁 | 缓存、计数器、锁 |
| Hash | 字段、对象 | 用户、购物车 |
| List | 有序、两端 | 队列、最新列表 |
| Set | 唯一、集合运算 | 标签、共同好友 |
| ZSet | 分数、排名 | 排行榜、延迟队列 |
| Bitmap | 位、布尔状态 | 签到、在线状态 |
| HyperLogLog | 近似去重 | UV |
| Bloom Filter | 一定不存在/可能存在 | 穿透防护 |
| Stream | 消息流、消费组 | 异步事件 |

## 三大缓存问题

```text
穿透：查不存在 → 参数校验 + Bloom Filter + 空值缓存
击穿：热点过期 → 互斥锁单飞或逻辑过期异步刷新
雪崩：大量失效/Redis故障 → 随机TTL + 限流降级 + 高可用
```

## 持久化与高可用

```text
RDB：快照，恢复快，可能丢最近写入
AOF：写命令，恢复点细，文件和重写成本更高
主从：复制副本，通常异步
Sentinel：监控与故障转移，不负责分片
Cluster：槽位分片 + 节点故障转移，跨槽操作更复杂
```

## 分布式锁

```text
SET key random-token NX EX seconds
释放：Lua 校验 token 后 DEL
风险：无 TTL、误删他人锁、TTL过短、重试风暴、事务边界不一致
```

## 案例答案骨架

```text
问题 → 约束 → 数据结构/缓存模式 → 原子机制
→ 一致性与高可用 → 性能与容量 → 故障兜底 → 指标验证
```
