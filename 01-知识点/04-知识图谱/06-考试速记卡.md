# 06 知识图谱考试速记卡

## 一句话

```text
知识图谱 = 用图结构组织实体、关系和属性，支持查询、关联和推理。
```

## 七阶段

```text
采集 → 清洗 → 抽取 → 表示 → 融合 → 存储 → 应用
```

## 抽取三件套

```text
NER：找实体
关系抽取：找实体之间的关系
属性抽取：找实体自身的特征
```

## 表示三件套

| 名称 | 关键词 |
|------|--------|
| RDF | 主体—谓词—客体、W3C、三元组 |
| OWL | 本体、类、属性、约束、语义推理 |
| 属性图 | 节点、关系、属性、路径查询 |

## 查询

```text
SPARQL：查询 RDF 三元组图
Cypher：查询属性图中的节点、关系和路径
```

## 融合

```text
实体对齐：不同来源的记录是不是同一个实体？
实体消歧：同一个名字到底指哪个实体？
冲突处理：不同来源说法不一致时依据什么取舍？
```

## 爬虫

```text
URL 调度器 → 网页下载器 → 内容解析器 → 数据存储器
        URL 去重、重试、限速、超时、失败队列
```

## 异步 I/O

```text
非阻塞 + 事件驱动 + I/O 密集场景提高并发/吞吐
```

## 图数据库选型五句法

```text
实体多、关系复杂、需要多跳查询
→ 节点/边/属性模型匹配
→ 避免复杂 JOIN 的关系表达
→ 支持路径和关联分析
→ 仍需结合事务、规模、索引和一致性评估
```

## 最容易丢分的区别

| 不要混淆 | 记忆 |
|----------|------|
| 抽取 / 表示 | 找知识 / 编码知识 |
| 实体对齐 / 消歧 | 合并同一实体 / 区分同名实体 |
| 问题分类 / 知识检索 | 判断意图 / 查询知识 |
| 模板匹配 / 模板翻译 | 匹配结构 / 转成查询 |
| RDF / OWL | 数据模型 / 语义本体语言 |
| 同步 I/O / 异步 I/O | 等待后继续 / 不等待先调度 |

