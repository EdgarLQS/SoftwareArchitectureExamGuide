# 03 知识表示、推理与查询

## 1. RDF：用三元组表达事实

RDF（Resource Description Framework）是一种资源描述框架。最基础的数据单元是：

```text
主体 Subject — 谓词 Predicate — 客体 Object
```

示例：

```text
<阿司匹林> <治疗> <头痛>
<阿司匹林> <剂型> "片剂"
```

当客体是另一个实体时，它通常可以继续连接其他关系；当客体是文字、数字或日期时，通常是字面值。

RDF 的重点是数据模型和语义连接，不要把 RDF/XML 误认为 RDF 本身。RDF/XML、Turtle、JSON-LD 是不同的序列化方式。

## 2. OWL 与本体

### 本体是什么

本体是对一个领域中概念、类别、属性、关系和约束的规范化描述。可以把它理解为：

```text
领域词典 + 分类体系 + 关系定义 + 约束规则
```

### OWL 做什么

OWL 在 RDF 等基础上提供更丰富的形式化语义，用于表达类、公理、属性和个体，并支持符合规则的推理。

例子：

```text
肺炎 是 呼吸系统疾病的子类
阿司匹林 治疗 肺炎
```

在适当的本体语义和关系定义下，系统可以推出更一般或更隐含的结论。但“能推理”不等于“所有自然语言常识都能自动推出”。

## 3. 属性图：节点、关系、属性

属性图通常表示为：

```text
(节点:实体 {属性}) -[关系 {关系属性}]-> (节点:实体 {属性})
```

示例：

```text
(药品:阿司匹林 {剂型:"片剂"})
  -[治疗 {来源:"药典", 更新时间:"2026-01"}]->
(疾病:头痛)
```

## 4. RDF 与属性图对比

| 维度 | RDF | 属性图 |
|------|-----|--------|
| 基本单元 | 主体—谓词—客体 | 节点、关系、属性 |
| 常见查询 | SPARQL | Cypher、Gremlin 等 |
| 标准化 | W3C 标准体系 | 多种实现和生态 |
| 强项 | 语义互操作、本体和标准推理 | 直观建模、路径查询、应用开发 |
| 常见存储 | RDF 三元组库 | Neo4j、JanusGraph、NebulaGraph 等 |

考试中可以写“RDF 更强调标准化语义表达，属性图更强调面向应用的图遍历”，但不要简单写成“RDF 一定强、属性图一定弱”。实际能力取决于实现、索引、数据模型和推理组件。

## 5. 知识推理

知识推理是根据已有显式知识和规则，得到新的隐含知识。

| 类型 | 依据 | 例子 |
|------|------|------|
| 规则推理 | IF-THEN 规则 | 如果 A 属于 B 且 B 属于 C，则 A 属于 C |
| 本体推理 | 类、属性和公理语义 | 子类关系、逆关系、对称关系、传递关系 |
| 图结构推理 | 路径、邻域、连通性 | 通过多跳路径发现间接关联 |
| 统计/表示学习 | 向量和模型概率 | 预测可能存在的关系 |

答题时要说明“推理依据”和“推理结果”，不能把模型预测当成已验证事实。

## 6. SPARQL 与 Cypher

### SPARQL：匹配 RDF 图模式

```sparql
SELECT ?drug
WHERE {
  ?drug :treats :Headache .
}
```

### Cypher：匹配属性图模式

```cypher
MATCH (d:Drug)-[:TREATS]->(:Disease {name: "头痛"})
RETURN d
```

记忆：

```text
RDF → SPARQL → 三元组模式
属性图 → Cypher → 节点和关系模式
```
