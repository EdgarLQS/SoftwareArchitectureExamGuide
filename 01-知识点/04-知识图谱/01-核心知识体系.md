# 01 核心知识体系：先把“图”看懂

## 1. 一句话理解

知识图谱就是：**把现实世界里的对象、对象之间的关系和对象的特征，组织成可以查询和推理的知识网络。**

例如，医院知识图谱可以记录：

```text
阿司匹林 ──治疗──> 头痛
头痛 ──属于──> 症状
阿司匹林 ──剂型──> 片剂
```

这里的“阿司匹林”“头痛”“症状”“片剂”是节点或值，“治疗”“属于”“剂型”是语义关系。

## 2. 四个最小概念

| 概念 | 小白解释 | 考试表达 | 示例 |
|------|----------|----------|------|
| 实体 Entity | 世界上能被单独谈论的对象 | 人、物、地点、组织、概念等 | 阿司匹林、肺炎 |
| 关系 Relation | 两个实体之间的联系 | 有方向或语义的边 | 药品—治疗—疾病 |
| 属性 Attribute | 某个实体自身的特征 | 键值或数据属性 | 药品—剂型—片剂 |
| 三元组 Triple | 一条最小知识事实 | 主体—谓词—客体 | `(阿司匹林, 治疗, 头痛)` |

三元组的三个位置：

```text
主体 Subject ──谓词 Predicate──> 客体 Object
     阿司匹林       治疗             头痛
```

不要把“关系”和“属性”死记成两种完全不同的数据结构。考试中常把属性写成三元组；工程上通常根据查询、约束和数据模型决定如何存储。

## 3. 知识图谱与搜索引擎

| 维度 | 关键词搜索 | 知识图谱 |
|------|------------|----------|
| 输入 | 关键词 | 实体、关系和语义问题 |
| 数据 | 文档和网页 | 结构化事实与关系网络 |
| 输出 | 文档列表 | 实体、关系、答案和证据 |
| 处理重点 | 匹配文本 | 识别、连接、查询和推理 |
| 典型场景 | 找资料 | 问答、推荐、风控、辅助决策 |

考试答题时不要写“搜索引擎没有语义能力”。更准确的表达是：知识图谱把非结构化信息组织成显式实体和关系，可支持结构化查询与多跳关系分析。

## 4. 从文本到答案

```text
原始文本：阿司匹林可用于缓解头痛，常见剂型为片剂。
       ↓ 知识抽取
(阿司匹林, 治疗, 头痛)
(阿司匹林, 剂型, 片剂)
       ↓ 知识表示与存储
图数据库或 RDF 三元组库
       ↓ 查询
“阿司匹林能缓解什么？”
       ↓
头痛
```

## 5. 一张总架构图

```text
数据源
  │
  ├─网页 / 数据库 / API / 文献 / 人工录入
  ↓
采集 → 清洗 → 抽取 → 表示 → 融合 → 存储 → 应用
                                  │        │
                                  │        ├─查询
                                  │        ├─问答
                                  │        └─推荐
                                  └─推理与质量校验
```

## 6. 考试与工程的两层答案

### 考试层

优先记住：

```text
数据采集 → 数据清洗 → 知识抽取 → 知识表示
→ 知识融合 → 知识存储 → 知识应用
```

知识抽取通常包括命名实体识别、关系抽取和属性抽取；应用层常见问题分类、模板匹配、模板翻译和知识检索。

### 工程层

真实系统还要考虑来源可信度、时间版本、权限、冲突处理、人工审核、增量更新、可观测性和查询性能。图数据库不是所有知识图谱的唯一存储方案，RDF 三元组库、关系库、搜索引擎和向量库可能组合使用。
