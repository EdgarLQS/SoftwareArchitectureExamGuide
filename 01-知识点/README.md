## 三、长文迁移规则

每篇知识长文按以下步骤处理：

```text
定位真实文件和历史来源
→ 建立独立核验说明
→ 标记版本、绝对化结论和技术风险
→ 生成当前精简指南或直接重构原文
→ 加入当前维护清单和自动校验
```

核验重点：

- 软件或协议版本是否变化；
- 固定性能数字是否缺少测试条件；
- “一定、完全、绝对、唯一”等结论是否成立；
- 示例代码是否具备异常、并发和安全边界；
- 历年考频统计是否受到缺题和重构资料影响；
- AI 辅助内容是否经过人工技术复核；
- 是否与当前论文记忆卡和案例专题口径一致。

## 四、当前资料边界

- 旧长文可能没有 YAML 元信息；
- 部分内容基于历史版本、旧题面统计或 Gemini 对话整理；
- 历年出现次数不代表官方命题概率；
- 命令和配置必须结合当前软件版本核验；
- 当前指南优先保证概念、边界和答题逻辑，不追求复制所有旧代码示例。
