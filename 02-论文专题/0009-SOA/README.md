## 历史资料说明

`03-SOA论文范文-改写版.md` 等旧文件保留历史素材，但可能存在：

- 将 SOA 等同于 SOAP、Web Service 或 ESB；
- 将 ESB 描述为必然单点；
- 将微服务或 Service Mesh 描述为 SOA 的简单替代；
- 服务契约缺少版本、兼容、SLO 和退役策略；
- 跨系统流程只列 Saga/TCC 名称，没有幂等、补偿和人工兜底；
- 未标记的模拟项目和指标。

当前训练以本 README、记忆卡、现行框架和 `2026H2` 主范文为准。

## 重点纠错

- SOA 是服务化原则与治理方法，不等于某一种协议或产品；
- 服务边界来自业务能力、数据所有权、事务和复用价值；
- 同步 API、消息、事件、批量和编排根据场景组合使用；
- ESB、API 网关、消息平台、服务目录和流程引擎职责不同；
- 契约包含业务语义、版本、兼容、错误、权限、容量和生命周期；
- 跨系统一致性需要可靠发布、幂等、补偿、状态查询和对账；
- SOA、微服务和事件驱动可以组合，而不是线性替代。
