# 系统安全架构设计论文写作框架

> 本框架按风险和题目要求组织，不再强制五段、固定字数或唯一“安全五特征”模型。

## 一、适用题型

- 论系统安全架构设计及其应用；
- 说明身份鉴别、访问控制、数据保护和审计；
- 说明零信任、纵深防御或威胁建模；
- 说明安全检测、响应、恢复和持续治理；
- 结合项目说明安全风险、架构决策和效果。

## 二、审题映射

| 题目要求 | 必须回答 |
|----------|----------|
| 安全目标 | 资产、机密性、完整性、可用性、真实性和审计需求 |
| 风险分析 | 数据流、信任边界、威胁、可能性和影响 |
| 架构设计 | 身份、授权、网络、应用、数据、供应链和监控 |
| 项目实践 | 攻击或风险现象、根因、控制、边界和验证 |
| 效果评价 | 风险下降、发现和处置时间、审计覆盖、恢复演练 |

## 三、推荐结构

```text
摘要
→ 项目资产、威胁、约束和本人职责
→ 安全原则与威胁建模
→ 分层安全架构和关键技术边界
→ 项目实践：预防、检测、响应和恢复
→ 效果、权衡和持续改进
```

## 四、风险驱动方法

```text
识别业务与数据资产
→ 绘制数据流和信任边界
→ 识别威胁和攻击路径
→ 评估可能性与影响
→ 选择预防、检测、响应和恢复控制
→ 通过测试、审计和演练验证
```

可以采用 STRIDE、攻击树、风险矩阵或组织标准，但应说明它们如何作用于具体资产，不能只列模型名称。

## 五、安全原则

| 原则 | 设计含义 | 典型措施 |
|------|----------|----------|
| 最小权限 | 只授予完成任务所需权限 | 默认拒绝、临时授权和定期回收 |
| 纵深防御 | 单层失守不导致全局失守 | 身份、网络、应用和数据多层控制 |
| 职责分离 | 关键操作由不同主体制约 | 双人复核、开发与发布分离 |
| 安全默认 | 初始配置保持安全 | 关闭非必要接口、强制加密 |
| 零信任 | 不因网络位置自动信任 | 持续鉴别、设备和上下文评估 |
| 可恢复性 | 假设防护可能失败 | 备份、容灾、应急响应和演练 |

安全目标和特征分类应以题目或采用的标准为准，不宣称 CIA 扩展形式是唯一体系。

## 六、分层安全架构

| 层次 | 重点控制 | 需要说明的风险 |
|------|----------|----------------|
| 身份 | MFA、短期令牌、账号生命周期和风险鉴别 | 凭据泄露、撞库和会话劫持 |
| 授权 | RBAC/ABAC、PDP/PEP、资源归属和租户隔离 | 越权和权限蔓延 |
| 网络与边界 | TLS、WAF、API 网关、微隔离和 DDoS 防护 | 扫描、注入和横向移动 |
| 应用 | 输入校验、依赖治理、安全编码和速率限制 | 注入、XSS 和业务滥用 |
| 数据 | 分类分级、加密、脱敏、密钥和备份 | 泄露、篡改和不可恢复 |
| 供应链与运维 | SBOM、制品签名、漏洞和变更审计 | 恶意依赖、镜像污染和未授权变更 |
| 检测响应 | SIEM、UEBA、告警编排和应急流程 | 发现过晚和告警噪声 |

## 七、关键技术边界

### 7.1 JWT 与会话

- JWT 是令牌格式，不天然安全或完全无状态；
- 使用标准协议、成熟算法和成熟库；
- 校验签名、发行者、受众、有效期和唯一标识；
- Access Token 短期有效，Refresh Token 轮换并可撤销；
- 高风险场景增加设备、行为和持续鉴别；
- 浏览器存储结合 XSS、CSRF 和 SameSite 设计。

不要自创签名组合，也不要把 Redis 黑名单与“完全无状态”同时描述为核心优势。

### 7.2 MFA

MFA 必须组合不同因素类型。短信 OTP 可用于中低风险场景，但抗钓鱼和抗 SIM 换卡能力有限；高风险后台优先使用硬件密钥或抗钓鱼认证。

### 7.3 密码、加密与签名

- 密码使用专用慢哈希算法和随机盐；
- 数据加密解决机密性；
- HMAC 解决共享密钥场景的完整性和真实性；
- 数字签名解决真实性、完整性并支持更强证据链；
- 密钥使用 KMS/HSM 管理生成、轮换、吊销和销毁；
- 盲索引只适合受限查询，不支持任意安全模糊查询。

## 八、检测、响应与恢复

```text
检测异常
→ 分级告警
→ 隔离账号、令牌、主机或网络路径
→ 保全证据并评估影响范围
→ 恢复服务和数据
→ 复盘并更新控制
```

恢复设计包括 RTO/RPO、不可变备份、恢复演练、跨区域容灾和通信机制。安全论文不能只写防护层。

## 九、项目实践框架

### 9.1 账号接管

```text
问题：撞库、异地登录和高风险账号接管
→ 证据：登录地、设备、失败次数和行为异常
→ 方案：风险评分、分级 MFA、令牌轮换和会话撤销
→ 风险：误判、用户体验和隐私
→ 验证：账号接管、挑战成功率和申诉量
```

### 9.2 跨租户越权

```text
问题：用户通过修改资源 ID 读取其他租户订单
→ 根因：只校验接口角色，未校验资源归属
→ 方案：RBAC+ABAC、PDP 集中决策、PEP 执行和审计
→ 验证：越权测试、敏感访问覆盖和权限回收时间
```

### 9.3 日志与证据

```text
问题：日志可被修改且缺少关联信息
→ 方案：集中收集、追加写/WORM、签名链、时间同步和 Trace ID
→ 边界：日志防篡改不自动等于不可抵赖
→ 验证：审计覆盖、完整性校验和事件追溯时间
```

### 9.4 供应链

```text
问题：依赖漏洞或镜像污染进入生产
→ 方案：依赖锁定、SBOM、漏洞扫描、制品签名和准入策略
→ 验证：高危漏洞修复时间和未经签名制品拦截率
```

## 十、模拟指标口径

| 指标 | 改造前 | 改造后 |
|------|--------|--------|
| 高危账号接管 | 基线 | 减少 90% |
| 敏感访问审计覆盖 | 60% | 100% |
| 高危告警发现时间 | 4 小时 | 5 分钟 |
| 平均处置时间 | 8 小时 | 30 分钟 |
| 恢复演练 | 不定期 | 每季度一次 |

均为训练模拟数据。不使用“零安全事件”“所有攻击无效”等绝对结论。

## 十一、摘要与总结

### 摘要

```text
项目资产与主要风险
→ 风险驱动的分层安全架构
→ 身份、数据、检测和恢复重点
→ 主要效果
→ 本文回应的题目要求
```

### 总结

```text
回扣风险与安全目标
→ 给出发现、处置和审计指标
→ 说明体验、性能和治理成本权衡
→ 给出针对性的安全演进
```

## 十二、检查单

- [ ] 从资产、数据流和威胁出发，而非只堆技术
- [ ] 认证、授权、加密、签名和审计概念清楚
- [ ] JWT、MFA 和密码方案符合成熟实践
- [ ] 包含密钥生命周期和供应链治理
- [ ] 预防、检测、响应和恢复形成闭环
- [ ] 安全控制说明限制和用户体验权衡
- [ ] 不使用绝对安全和伪精确结论
- [ ] 模拟指标与记忆卡和范文一致
- [ ] 能在规定时间内用纯文字完成
