# 系统安全架构范文训练评价 v2

> 评估对象：`03-系统安全架构设计论文范文-改写版.md`
>
> 评价性质：内部训练复盘，非官方评分。原 `71/75` 已取消。

## 一、总体判断

当前等级：**revise（待修订）**。

优点：

- 能从身份、权限、数据和审计多个层面组织安全方案；
- 包含最小权限、纵深防御和持续治理意识；
- 有鉴别、访问控制、加密和监控实践素材；
- 项目背景适合迁移到安全架构类题目。

主要风险：

- 将 CIA 扩展分类写成唯一“信息安全五特征”；
- PDR/PDRR 公式和结论表达过度简化；
- JWT、SM3、Redis 黑名单等组合容易形成自创协议或伪无状态；
- 短信 MFA、安全问题和高风险认证的安全等级区分不足；
- 加密、签名、HMAC、密码哈希和不可抵赖概念可能混用；
- “零事故”“攻击无效”等绝对结果不可验证；
- 缺少威胁建模、资产分级、供应链和恢复闭环。

| 主题 | 状态 | 修订建议 |

## 三、关键修订

### 3.1 身份与令牌

JWT 是令牌格式，不天然安全或完全无状态。至少需要校验签名、发行者、受众、有效期和唯一标识，并设计 Refresh Token 轮换、撤销和设备风险策略。

不要自创“HS256/SM3 JWT”或把通用摘要算法直接当作成熟令牌签名方案。算法选择应使用标准协议、成熟库和组织认可的密码套件。

### 3.2 密码与加密

- 用户密码使用 Argon2、scrypt、bcrypt 或合规专用方案，不用快速摘要直接存储；
- 数据加密、HMAC 和数字签名分别解决不同问题；
- 密钥与密文分离，建立生成、使用、轮换、吊销和销毁流程；
- 盲索引适合受限查询，不等于安全的任意模糊查询；
- 日志和备份同样需要分类分级和访问控制。

### 3.3 安全闭环

```text
资产和数据流
→ 威胁建模
→ 风险评估
→ 预防控制
→ 检测告警
→ 响应隔离
→ 恢复与证据保全
→ 复盘和控制更新
```

## 四、模拟指标建议

| 指标 | 改造前 | 改造后 |
|------|--------|--------|
| 高危账号接管 | 基线 | 减少 90% |
| 敏感访问审计覆盖 | 60% | 100% |
| 高危告警发现时间 | 4 小时 | 5 分钟 |
| 平均处置时间 | 8 小时 | 30 分钟 |
| 恢复演练 | 不定期 | 每季度完成一次 |

不使用“攻击全部无效”“零安全事件”等绝对结论。

## 五、优先修订清单

- [ ] 标记项目和指标为模拟数据
- [ ] 增加资产识别、数据流和威胁建模
- [ ] 修正 JWT 和密码存储方案
- [ ] 区分认证、授权、加密、签名和审计
- [ ] 增加密钥生命周期与供应链安全
- [ ] 增加检测、响应、恢复和演练
- [ ] 删除无来源的固定模型与绝对安全结论
- [ ] 核对记忆卡、框架和范文术语与指标

## 六、提升为 stable 的条件

```text
风险驱动而非技术堆叠
身份和密码方案符合标准实践
授权与数据保护边界清楚
检测响应恢复形成闭环
指标可验证且不绝对化
限时迁移写作无重大遗漏
```
