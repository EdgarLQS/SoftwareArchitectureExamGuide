## 历史资料说明

`03-软件维护论文范文-改写版.md` 等旧文件保留历史素材，但可能包含：

- 无来源的维护类型比例和生命周期成本比例；
- 固定圈复杂度、覆盖率和技术债阈值；
- MTBF、MTTR、可用性和故障次数口径不一致；
- 固定 20% 技术债容量等绝对规则；
- 未标记的模拟项目和指标。

当前训练以本 README、记忆卡、现行框架和 `2026H2` 主范文为准。

## 重点纠错

- 四类维护用于说明变更目的，不决定唯一流程；
- 维护比例和维护成本比例需要来源与统计口径；
- 覆盖率和圈复杂度是风险信号，不是所有模块统一质量线；
- 变更流程按风险分级，不让所有修改进入重审批；
- 重构前建立特征测试和运行基线；
- 可靠性指标使用相同时间窗口和故障定义；
- 技术债按风险和价值排序，不机械预留固定容量。
