# 系统性能测试范文训练评价

> 评估对象：`03-系统性能测试论文范文-改写版.md`
>
> 评价性质：内部训练复盘，非官方评分。原固定分值和“结构不合格”结论已取消。

## 一、总体判断

当前等级：**usable（可用）**。

优点：

- 能从业务峰值、尾延迟和资源瓶颈引出性能测试；
- 覆盖负载建模、压测工具、链路观测和瓶颈优化；
- 有慢查询、缓存穿透和连接池问题素材；
- 具备迁移到性能测试、容量规划和高并发题目的基础。

主要风险：

- 把负载、压力、稳定和并发写成唯一固定四类；
- 把 P99<200ms、资源利用率 70% 写成通用阈值；
- 使用“80/20 法则×3 倍”作为通用 TPS 估算公式；
- 盲目扩大数据库连接池可能转移和放大瓶颈；
- 1:4 缩比环境直接推算生产性能缺少校准；
- 成本节省、可用性提升和测试结果之间缺少充分证据；
- 项目和效果指标属于模拟数据但标注不足。

## 二、技术审查

| 主题 | 状态 | 修订建议 |
|------|------|----------|
| 测试分类 | 待修订 | 根据目标选择基线、负载、压力、峰值、耐久、容量和故障测试 |
| SLO | 可用 | 由业务旅程和风险确定，不采用固定 P99 阈值 |
| 负载模型 | P0 | 基于历史日志、峰值窗口、请求比例和增长预测 |
| 环境模型 | 待加强 | 记录与生产差异并校准缩比关系 |
| 数据准备 | 可用 | 补充数据分布、冷热、账户和隐私脱敏 |
| 观测 | 可用 | 关联业务、应用、数据库、缓存、消息和基础设施指标 |
| 连接池 | P0 | 根据数据库并发能力和查询时长计算，不直接扩到 200 |
| 缓存 | 可用 | 修正 Cache-Aside 和穿透治理口径 |
| 成本 | 待修订 | 通过容量和账单分析验证，不由一次压测直接推导 |
| 模拟数据 | 待统一 | 与记忆卡和框架保持一致 |

## 三、关键修订

### 3.1 测试目标

```text
业务关键旅程
→ SLO 和容量目标
→ 真实负载模型
→ 测试类型与停止条件
→ 分层观测
→ 瓶颈假设与验证
→ 回归和持续化
```

### 3.2 资源阈值

CPU、连接、线程、IO、队列和外部依赖的饱和点不同。重点是吞吐停止增长、延迟快速上升和错误率增加的拐点，而不是统一 70%。

### 3.3 连接池

连接池过大可能导致数据库上下文切换、锁竞争和内存压力。应根据：

- 数据库最大并发；
- 查询平均与尾延迟；
- 应用实例数量；
- 排队和超时策略；
- 数据库连接预算；

计算并通过压测验证。

## 四、模拟指标建议

| 指标 | 优化前 | 优化后 |
|------|--------|--------|
| 峰值吞吐 | 3000 TPS | 35000 TPS |
| P99 | 5 秒以上 | 150ms |
| 错误率 | 0.15% | 少于 0.02% |
| 缓存命中率 | 60% | 95% |
| 72 小时耐久测试 | 延迟持续劣化 | 无持续劣化 |

成本和可用性应单独验证，不与性能测试结果机械绑定。

## 五、优先修订清单

- [ ] 标记项目、负载和指标为模拟数据
- [ ] 将固定四类改为按测试目标选择
- [ ] 删除通用 TPS 公式和固定资源阈值
- [ ] 校准缩比环境与生产差异
- [ ] 重写连接池调整依据
- [ ] 增加压测机瓶颈和测试停止条件
- [ ] 补充正确性、韧性和成本副作用验证
- [ ] 核对记忆卡、框架和范文指标

## 六、提升为 stable 的条件

```text
负载模型来自可解释业务假设
SLO和测试类型匹配
瓶颈定位有监控证据
容量和连接预算正确
结果可重复且指标一致
限时迁移写作无重大遗漏
```
