# 软件架构风格范文训练评价

> 评估对象：`04-软件架构风格论文范文-改写版.md`
>
> 评价性质：内部训练复盘，非官方评分。原“44/75、不及格”结论基于自定义模板，已取消。

## 一、总体判断

当前等级：**usable（可用）**。

优点：

- 项目背景能够支持仓库风格和读写分离讨论；
- 能说明构件、连接件、质量属性和选型；
- 实践包含缓存、主从复制和副本延迟问题；
- 具备迁移到架构风格比较、质量属性和混合架构题目的素材。

主要风险：

- 把“固定五段”和理论字数当作确定评分依据；
- 读写分离被描述为仓库风格的唯一或标准变体；
- Cache-Aside 写路径曾被写成同步更新缓存；
- CAP 被简化为直接选择 AP；
- “层次风格安全性最高”等绝对比较缺少场景；
- 模拟指标未充分标注，多个文件可能存在不同基线。

## 二、技术审查

| 主题 | 状态 | 修订建议 |
|------|------|----------|
| 五类架构风格 | 可用 | 作为常见分类框架，不宣称唯一标准 |
| 构件与连接件 | 稳定 | 结合具体系统说明，不只背定义 |
| 质量属性 | 待加强 | 使用场景和响应度量分析，而非固定排名 |
| 仓库风格 | 可用 | 说明统一数据视图、耦合和单点数据治理 |
| 读写分离 | 待加强 | 说明副本延迟、路由、故障切换和读己之写 |
| Cache-Aside | P0 | 写路径采用更新数据库后删除缓存 |
| CAP | P0 | 分区发生时讨论一致性和可用性取舍，不使用简单 AP 口号 |
| 模拟数据 | 待统一 | 与记忆卡和写作框架使用同一组数据 |

## 三、关键修订

### 3.1 架构风格选型

```text
业务目标和约束
→ 识别质量属性场景
→ 比较候选风格的构件、连接件和约束
→ 分析敏感点、风险和权衡
→ 选择主风格并补充必要战术
```

实际系统通常是混合架构。仓库风格可以与分层、适配器、事件和缓存组合使用。

### 3.2 Cache-Aside

```text
读：查缓存→未命中查数据库→回填缓存
写：更新数据库并提交→删除缓存→必要时重试或延迟校验
```

### 3.3 一致性

- 普通查询可以接受短暂副本延迟；
- 写后立即读取的关键场景可临时读主；
- 使用版本号、提交时间或会话令牌识别新数据；
- 副本延迟超阈值时摘除或回退；
- 具体策略比“选择 AP”更有得分价值。

|------|--------|--------|
| QPS | 500 | 6000+ |
| P99 | 8 秒 | 400ms |
| 可用性 | 99.5% | 99.99% |
| 主库 CPU | 95% | 45% |
| 写后可查率 | 60% | 98% |

## 五、优先修订清单

- [ ] 标记项目和指标为模拟数据
- [ ] 修正 Cache-Aside 写路径
- [ ] 删除架构风格质量属性的绝对排名
- [ ] 用具体一致性场景替代 CAP 口号
- [ ] 说明主从切换、延迟和读己之写
- [ ] 强调混合架构和质量属性战术
- [ ] 核对记忆卡、框架和范文指标
- [ ] 用新题完成一次限时迁移写作

## 六、提升为 stable 的条件

```text
风格定义和边界准确
质量属性分析有场景和度量
缓存与副本一致性方案正确
混合架构权衡清楚
指标前后一致
限时迁移写作无重大遗漏
```
