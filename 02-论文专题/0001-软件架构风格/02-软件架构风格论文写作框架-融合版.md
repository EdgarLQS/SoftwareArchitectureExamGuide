# 软件架构风格论文写作框架

> 文件名保留“融合版”仅为兼容历史链接。当前内容按题目要求驱动，不再强制五段、固定字数、固定过渡句或固定“我/我们”次数。

## 一、适用题型

- 论某种软件架构风格及其应用；
- 比较多种架构风格并完成选型；
- 说明架构风格对质量属性的影响；
- 结合项目说明混合架构的设计与演进；
- 说明架构评估、风险与权衡。

## 二、审题映射

| 题目要求 | 必须回答 |
|----------|----------|
| 说明架构风格 | 定义、构件、连接件、约束、控制与数据关系 |
| 分类或比较 | 使用统一维度比较，不只列名称 |
| 说明选型 | 业务目标、质量属性、候选方案、风险和权衡 |
| 结合项目 | 具体问题、设计决策、实施、故障治理和指标 |
| 评价效果 | 基线、改造结果、验证条件、不足和后续演进 |

## 三、推荐结构

```text
摘要
→ 项目背景、质量属性和本人职责
→ 题目要求的风格定义或分类
→ 候选风格比较与选型
→ 项目架构设计与三组实践因果链
→ 效果、不足和架构演进
```

题目若只要求一种风格，不必完整展开所有分类；题目要求比较时，必须覆盖指定风格和比较维度。

## 四、理论准备

### 4.1 风格描述模板

每种风格至少说明：

```text
风格名称
→ 核心构件
→ 连接件
→ 数据与控制关系
→ 组合约束
→ 主要质量属性影响
→ 适用场景与限制
```

### 4.2 常见分类框架

| 类别 | 典型构件与连接件 | 常见场景 | 主要注意点 |
|------|------------------|----------|------------|
| 数据流 | 过滤器、管道 | ETL、编译和流处理 | 状态、错误处理和交互性 |
| 调用返回 | 模块、对象、层、调用 | 企业应用、分层系统 | 同步耦合和调用链 |
| 独立构件 | 进程、服务、事件、消息 | 分布式和异步系统 | 顺序、幂等和可观测性 |
| 虚拟机 | 解释器、规则、执行环境 | DSL、规则引擎 | 性能、调试和规则治理 |
| 仓库/共享数据 | 中央存储、访问接口 | 数据共享、知识系统 | 数据耦合、容量和一致性 |

该表是常见分析框架，不宣称是所有教材唯一分类。黑板与数据库仓库虽然都属于共享数据方向，但控制方式和适用问题不同。

## 五、选型与质量属性

### 5.1 质量属性场景

```text
刺激源
→ 刺激
→ 环境
→ 制品
→ 响应
→ 响应度量
```

选型不能只写“某风格性能最好”。必须结合具体场景，例如：

> 大促高峰下，外部用户访问轨迹查询服务，系统通过只读副本、缓存和限流保持 P99 小于 500ms，核心查询错误率小于 0.1%。

### 5.2 比较维度

| 维度 | 需要回答的问题 |
|------|----------------|
| 性能 | 能否并行、是否有网络与存储瓶颈 |
| 可用性 | 单点、故障传播、恢复和降级方式 |
| 可修改性 | 变更影响面、接口和依赖方向 |
| 扩展性 | 能否按热点能力独立扩容 |
| 一致性 | 数据所有权、复制和事务边界 |
| 安全 | 信任边界和策略集中位置 |
| 成本 | 迁移、开发、运维和团队能力 |

### 5.3 混合架构

实际系统通常不是单一风格。推荐表达：

```text
以仓库风格提供统一数据事实来源
+ 以分层风格隔离职责
+ 以适配器隔离外部供应商变化
+ 以事件驱动处理异步通知
+ 以缓存和限流补充性能与可用性战术
```

明确哪些是架构风格，哪些是设计模式或质量属性战术。

## 六、项目实践框架

### 6.1 实践一：异构接入

```text
问题：供应商协议和状态码不一致
→ 根因：外部模型直接侵入核心领域
→ 方案：适配器、防腐层和标准领域模型
→ 风险：适配器膨胀和测试成本
→ 验证：新供应商接入周期和故障影响下降
```

### 6.2 实践二：读写竞争

```text
问题：单库同时承载写入、查询和报表
→ 证据：主库 CPU、慢查询和 P99 上升
→ 候选：单库优化、读写分离、分片
→ 决策：当前规模先采用一主多从和查询路由
→ 风险：副本延迟和故障切换
→ 验证：查询延迟、主库负载和可查率
```

### 6.3 实践三：缓存一致性

Cache-Aside 正确口径：

```text
读：查缓存→未命中查数据库→回填缓存
写：更新数据库并提交→删除缓存→失败重试或延迟校验
```

补充穿透、击穿、雪崩和热点保护，但不要把缓存描述为系统事实来源。

### 6.4 副本一致性

- 普通读取允许短暂最终一致；
- 写后立即读取的关键请求可短时间读主；
- 通过版本、时间或会话令牌识别新数据；
- 副本延迟超阈值时摘除；
- 不用一句“选择 AP”替代具体一致性设计。

## 七、模拟指标口径

与记忆卡统一：

| 指标 | 改造前 | 改造后 |
|------|--------|--------|
| QPS | 500 | 6000+ |
| P99 | 8 秒 | 400ms |
| 可用性 | 99.5% | 99.99% |
| 主库 CPU | 95% | 45% |
| 写后可查率 | 60% | 98% |

这些数据属于训练模拟，不代表真实生产结果。范文若使用其他项目，应同步修改全文所有指标。

## 八、摘要骨架

```text
项目与问题
→ 目标架构风格及选择原因
→ 关键设计与实施
→ 主要效果
→ 本文重点论述的题目要求
```

不要在摘要中罗列全部五类风格，也不要写过多配置细节。

## 九、总结骨架

```text
回扣风格如何满足质量属性
→ 给出最重要的验证指标
→ 说明副本延迟、缓存一致性或数据耦合等不足
→ 给出针对性的演进方向
```

## 十、检查单

- [ ] 题目要求的风格和比较维度全部回应
- [ ] 构件、连接件和约束描述准确
- [ ] 风格、模式、战术和技术产品没有混淆
- [ ] 选型有质量属性场景和候选方案
- [ ] Cache-Aside 写路径正确
- [ ] 一致性策略具体，不只写 CAP 口号
- [ ] 项目实践包含问题、证据、方案、风险和效果
- [ ] 模拟指标与记忆卡和范文一致
- [ ] 文章能够在规定时间内用纯文字完成
