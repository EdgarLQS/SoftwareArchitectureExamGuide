# 大数据架构范文训练评价 v2

> 评估对象：`03-大数据架构论文范文-改写版.md`
>
> 评价性质：内部训练复盘，非官方评分。原 `71/75` 已取消。

## 一、总体判断

当前等级：**revise（待修订）**。

优点：

- 能从离线延迟、实时分析和规模增长引出大数据架构；
- 覆盖消息、流处理、批处理、OLAP 和湖仓方向；
- 有背压、倾斜、异步关联和一致性实践素材；
- 可迁移到 Lambda/Kappa、实时计算和湖仓类题目。

主要风险：

- Lambda、Kappa 和 Lakehouse 的优缺点存在绝对化表述；
- 把 Flink Checkpoint 直接等同端到端 Exactly-Once；
- Watermark、迟到数据和事件时间边界描述不完整；
- 盲目增加并行度可能加重下游背压，原文治理链需要调整；
- 峰值 TPS、零误差和成本下降等指标缺少容量依据；
- 湖仓一体被描述为自动消除双链和一致性问题；
- 模拟数据与范文、故事线、记忆卡可能存在多套基线。

## 三、关键修订

### 3.1 端到端一致性

Checkpoint 只保证计算状态可以一致恢复。端到端语义还需要：

```text
可重放或事务化 Source
+ 一致状态快照
+ 事务或幂等 Sink
+ 稳定业务主键与去重
+ 外部副作用的协调或补偿
```

“Exactly-Once”也不等于业务数据绝对零误差，仍需要数据质量、对账和补数。

### 3.2 Watermark

Watermark 是对事件时间进度的估计。允许迟到越长，结果可能更完整，但状态、延迟和资源成本越高。超过窗口的数据需要侧输出、更新结果或离线补偿。

### 3.3 湖仓一体

湖仓表格式可以统一数据基础并提供 ACID、Schema 演进和 Time Travel，但不会自动解决业务语义、双链代码、实时服务和所有引擎兼容问题。

## 四、模拟指标建议

| 指标 | 改造前 | 改造后 |
|------|--------|--------|
| 数据可见延迟 | 4—8 小时 | 少于 2 秒 |
| 实时查询 P99 | 无实时服务 | 少于 100ms |
| 峰值处理能力 | 3 万 TPS | 30 万 TPS |
| 对账差异 | 0.5% | 少于 0.01% |
| Checkpoint 时间 | 30 分钟或超时 | 少于 2 分钟 |
| 热点算子 CPU | 95% | 60%—70% |
| 存储成本 | 基线 | 降低 35% |

```text

全部模拟指标一致
限时迁移写作无重大遗漏
```
