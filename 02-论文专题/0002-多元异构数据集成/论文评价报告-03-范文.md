# 多元异构数据集成范文训练评价

> 评估对象：`04-多元异构数据集成论文范文-改写版.md`
>
> 评价性质：内部训练复盘，非官方评分。原“39/75、不及格”结论基于自定义结构模板，已取消。

## 一、总体判断

当前等级：**usable（可用）**。

优点：

- 项目背景覆盖多系统、多协议和供应链数据场景；
- 能从格式、结构和语义差异讨论异构；
- 覆盖 CDC、消息、湖仓、元数据和数据服务；
- 有 Schema 变化、源库压力和语义冲突实践素材。

主要风险：

- 把十段或五段结构差异直接换算成考试分数；
- 把 CDC 描述为完全“零侵入”；
- 把数据联邦描述为天然会拖垮源库；
- 把 Iceberg Schema Evolution 写成可自动处理所有 Schema Drift；
- LLM 语义对齐效果缺少样本、准确率和人工审批边界；
- ETL、CDC、API、联邦和消息被写成互斥方案，忽略组合使用；
- 模拟指标和多个文件的基线可能不一致。

## 二、技术审查

| 主题 | 状态 | 修订建议 |
|------|------|----------|
| 异构分类 | 可用 | 作为分析框架，不宣称唯一四层体系 |
| 集成选型 | 待加强 | 根据时效、一致性、源端影响、重算和成本组合方案 |
| CDC | P0 | 补充快照、日志权限、DDL、重复、顺序和资源开销 |
| 数据联邦 | 待修订 | 说明查询下推、资源隔离和适用的低频场景 |
| Schema 演进 | P0 | 区分兼容结构变化与业务语义变化 |
| 元数据 | 可用 | 增加技术、业务、运营元数据和责任人 |
| 主数据 | 待加强 | 明确权威来源、匹配合并和 Golden Record |
| LLM 辅助 | 待加强 | 保留人工复核、置信度和评估集 |
| 模拟数据 | 待统一 | 与记忆卡和框架使用同一组基线 |

## 三、关键修订

### 3.1 组合式集成

```text
批量历史数据使用 ETL/ELT
+ 数据库增量使用 CDC
+ 业务命令与查询使用 API
+ 异步业务事实使用事件
+ 低频不复制数据使用联邦查询
```

项目通常采用组合，而不是选择一个方案替代所有其他方式。

### 3.2 Schema 与语义

表格式和 Schema Registry 可以管理字段版本、兼容性和部分类型变化，但不能自动判断“销售额”定义是否改变。语义变化需要业务术语、指标口径、数据负责人和变更审批。

### 3.3 LLM 辅助

LLM 可用于字段候选匹配、文档生成和异常提示，但必须：

- 使用标注样本评估准确率；
- 输出置信度和可解释依据；
- 由业务负责人确认关键语义；
- 保护敏感数据；
- 保留人工回退和审计。

## 四、模拟指标建议

| 指标 | 改造前 | 改造后 |
|------|--------|--------|
| 数据可见延迟 | 24 小时 | 3 分钟 |
| 峰值处理能力 | 8 万 TPS | 12 万 TPS |
| 新数据源接入 | 3 人天 | 0.5 人天 |
| Schema 故障恢复 | 2—8 小时 | 15 分钟 |
| 源库 CPU | 90% | 35% |
| 高频查询 P99 | 3 秒 | 50ms |
| 关键语义冲突 | 基线 | 减少 60% |

## 五、优先修订清单

- [ ] 标记项目和指标为模拟数据
- [ ] 修正 CDC“零侵入”表述
- [ ] 将集成方式改为组合式选型
- [ ] 区分结构演进和语义变化
- [ ] 补充主数据、数据契约和责任人
- [ ] 为 LLM 辅助增加评估和人工审核
- [ ] 增加数据质量、血缘、补数和安全治理
- [ ] 核对记忆卡、框架和范文全部指标

## 六、提升为 stable 的条件

```text
异构层次和集成方式边界准确
Schema与语义治理清楚
数据质量和责任闭环完整
LLM使用可验证且有人审
指标前后一致
限时迁移写作无重大遗漏
```
