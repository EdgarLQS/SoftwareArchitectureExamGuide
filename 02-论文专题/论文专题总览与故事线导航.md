## 二、使用顺序

### 快速复习

```text
大纲记忆卡
→ 脱稿复述论文主线
→ 核对关键术语和量化指标
→ 用 10—15 分钟列一个新题提纲
```

### 深度复习

```text
核心知识点
→ 写作框架
→ 故事线
→ 通用范文
→ 评价报告
→ 限时重写
```

### 考前收口

只保留：

- 六条稳定论文主线；
- 每条主线一份记忆卡；
- 一个稳定、可迁移的项目背景；
- 每条主线 3—5 个问题—方案—效果因果链；
- 经过统一的数据和术语清单。

## 三、六条论文主线

### 主线 1：架构风格与架构评估

覆盖：软件架构风格、ABSD、质量属性、ATAM/SAAM 和混合架构。

```text
业务变化
→ 识别质量属性
→ 候选架构风格
→ 场景与权衡分析
→ 选择或组合架构
→ 迭代验证
```

适合回答：架构风格、架构设计方法、架构评估和质量属性相关题目。

### 主线 2：微服务与云原生

```text
单体太重，所以拆分
→ 乱拆导致分布式单体，所以用 DDD 划边界
→ 服务变多，所以引入注册、配置、熔断和追踪
→ 环境不一致，所以容器化
→ 容器规模增长，所以用 Kubernetes 编排
→ 发布频繁，所以建设 CI/CD、GitOps 和可观测性
```

适合回答：微服务、云原生、容器化、平台工程和 DevOps 相关题目。

### 主线 3：SOA、事件驱动与系统集成

```text
系统孤岛
→ 服务封装与契约
→ ESB 或 API 集成
→ 同步耦合和峰值压力
→ 事件发布订阅与消息队列
→ 幂等、顺序、重试和最终一致性治理
```

适合回答：SOA、企业集成、事件驱动、消息中间件和异步解耦相关题目。

### 主线 4：数据集成与大数据架构

```text
识别异构
→ 元数据映射
→ 主数据统一语义
→ 数据质量治理
→ 批流处理与 Lambda/Kappa
→ 湖仓一体
→ 数据契约、血缘和成本治理
```

适合回答：多源异构数据、大数据、湖仓、实时计算和数据治理相关题目。

### 主线 5：性能优化与高并发

```text
建立性能基线
→ 缓存与限流前置保护
→ 无状态化和水平扩容
→ 异步化缩短主链路
→ 数据库和存储优化
→ 压测、监控和容量治理
```

适合回答：高并发、性能优化、负载均衡、秒杀和性能测试相关题目。

### 主线 6：测试、安全与软件维护

```text
功能正确
→ 自动化与质量左移
→ 性能和稳定性验证
→ 安全威胁建模与纵深防御
→ 上线后的监控、缺陷和变更治理
→ 重构、维护和技术债控制
```

适合回答：软件测试、系统安全、软件维护、质量保证和持续改进相关题目。

## 四、专题故事线速记

### 多元异构数据集成

```text
识异构，选路线
→ 元数据，对字段
→ 主数据，统语义
→ 质量六维，保可信
→ 湖仓演进，抗变化
→ 分片反压，扛规模
→ 契约血缘，做治理
```

### 测试

```text
能不能用
→ 好不好用
→ 扛不扛得住
→ 能不能长期稳定
→ 改了会不会坏
→ 自动化能否降低成本
→ 质量能否前移到研发过程
```

### 微服务与云原生

```text
单体太重，所以拆
→ 服务太多，所以治理
→ 环境太乱，所以容器化
→ 容器太多，所以编排
→ 发布太频繁，所以流水线化
→ 规模变大，所以建设可观测、成本和安全治理
```

### 大数据架构

```text
批处理太慢，建设实时链路
→ 快和准难兼得，引入批流协同
→ 吞吐上升，治理背压
→ 数据分布不均，处理倾斜
→ 实时关联太慢，引入异步 I/O
→ 双链维护太重，走向湖仓统一
→ 规模扩大，精细治理成本
```

### 性能优化

```text
先测量，不凭感觉优化
→ 缓存和限流止血
→ 无状态和扩容提升容量
→ 异步化缩短关键路径
→ 数据库优化处理根因
→ 以压测和监控验证效果
```

## 五、论文项目背景复用规则

建议保留一个稳定项目背景，再针对题目调整技术主线。稳定信息包括：

- 项目类型和建设目标；
- 用户规模和核心业务；
- 本人担任系统架构师；
- 负责架构设计、技术选型和落地治理；
- 3—5 个可迁移的业务痛点；
- 一组经过统一的模拟或脱敏指标。

不能只替换技术名词。每次迁移必须重新检查：

1. 问题是否真的需要该技术；
2. 技术选型是否符合质量属性；
3. 方案是否与项目规模匹配；
4. 效果是否能由措施合理解释；
5. 题目要求是否全部回应。
