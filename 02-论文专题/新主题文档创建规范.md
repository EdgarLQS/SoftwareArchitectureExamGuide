# 论文专题新主题文档创建规范

> 本规范适用于 `02-论文专题/` 下新增或重构论文主题。当前目录统一使用四位数字编号，并区分复习资料、考场范文、来源可信度和模拟数据。

## 一、基本原则

1. **结构一致**：目录和核心文件命名可预测。
2. **题目驱动**：内容回应考试题目，不机械套固定段数或字数。
3. **技术正确**：定义、边界、失败和恢复经过人工复核。
4. **来源清楚**：官方、真题、参考、个人记录和 AI 辅助明确区分。
5. **数据透明**：论文项目和指标标记真实、脱敏或模拟。
6. **避免重复**：已有主题能够覆盖时，优先补充或重构。
7. **可限时使用**：记忆卡、框架和范文支持脱稿和限时写作。

不要以“表格数量”“篇幅越长越好”作为完成标准。

## 二、目录命名

每个主题使用：

```text
四位数字编号-主题名称
```

示例：

```text
0001-软件架构风格/
0004-微服务/
0011-性能优化/
0012-事件驱动架构/
```

规则：

- 编号固定为四位数字；
- 新编号从当前最大编号递增；
- 不因优先级变化重新编号；
- 名称使用考试常见术语；
- 避免同时存在多个近义目录；
- 重命名后同步修复全部相对链接和导航。

## 三、标准目录结构

```text
02-论文专题/
  0012-{主题名称}/
    README.md                             # 文件较多或有历史资料时建议
    00-大纲记忆卡.md
    01-{主题名称}核心知识点.md
    02-{主题名称}论文写作框架.md
    03-{主题名称}论文范文-2026H2.md
    04-{主题名称}论文评价报告.md          # 可选
    05-{主题名称}故事线.md                # 可选
```

### 必需文件

| 文件 | 用途 | 完成标准 |
|------|------|----------|
| `00-大纲记忆卡.md` | 考前快速回忆 | 能恢复题目映射、核心决策、实践因果链和统一指标 |
| `01-核心知识点.md` | 技术知识库 | 定义准确，覆盖原理、边界、比较、风险和来源 |
| `02-论文写作框架.md` | 审题与结构设计 | 题目驱动，包含选型、实践、指标和检查单 |
| `03-论文范文-2026H2.md` | 限时写作参考 | 纯文字、切题、技术正确、指标一致、声明模拟数据 |

### 可选文件

- `README.md`：有多版本、旧资料或多个范文时用于明确当前文件。
- `04-论文评价报告.md`：记录内部等级、技术风险和修订清单。
- `05-故事线.md`：用问题演进和因果链辅助记忆。

不要为了满足目录形式创建空文件。

## 四、统一元信息

当前文件建议加入：

```yaml
---
id: essay-0012-memory
title: 事件驱动架构论文大纲记忆卡
type: memory-card
status: reviewed
applicable_exam: 2026-H2
source_level:
  - reference
  - ai_assisted
scenario_data: simulated
updated_at: 2026-07-31
---
```

### `type` 推荐值

| 文件 | `type` |
|------|--------|
| 记忆卡 | `memory-card` |
| 核心知识点 | `knowledge` |
| 写作框架 | `writing-framework` |
| 范文 | `essay-sample` |
| 评价报告 | `essay-review` |
| 导航 | `navigation` |

### `status`

```text
draft → structured → reviewed → verified
                         ↓
                    deprecated → archived
```

AI 辅助内容不能仅因格式完整而直接标记 `verified`。

## 五、记忆卡规范

### 必需内容

1. 题目与适用方向；
2. 项目背景和模拟数据声明；
3. 理论或方法主线；
4. 架构选型或实施顺序；
5. 2—4 组问题—原因—方案—效果；
6. 统一指标；
7. 技术边界和考场注意事项。

### Mermaid 规则

- 使用 `graph TD` 或 `flowchart LR`；
- 节点文本使用双引号；
- 换行使用 `<br/>`；
- 避免过长单节点；
- 图中指标与范文一致；
- 图用于复习，范文必须能用纯文字表达。

记忆卡不是把整篇范文压入一张图，而是恢复因果链和关键决策。

## 六、核心知识点规范

至少覆盖：

```text
定义和目标
→ 组成或流程
→ 原理
→ 候选方案比较
→ 适用场景
→ 限制和失败模式
→ 运行与治理
→ 考题映射
→ 来源和最近核验日期
```

禁止：

- 把某一教材分类写成唯一标准；
- 把产品名当作架构原理；
- 使用“天然、绝对、完全零侵入”等无条件结论；
- 使用无来源的固定比例和阈值；
- 只讲成功路径，不讲故障和恢复。

## 七、写作框架规范

### 必需章节

1. 适用题型；
2. 审题映射；
3. 推荐结构；
4. 核心理论或方法；
5. 架构选型和权衡；
6. 项目实践框架；
7. 模拟指标口径；
8. 摘要和总结骨架；
9. 技术检查单。

### 禁止作为官方规则

- 正文必须恰好五段；
- 摘要或正文必须精确落在某个字数区间；
- “我”或“我们”必须出现固定次数；
- 必须使用固定数量的过渡句；
- 每篇必须恰好三组问题；
- 检查表全部通过即为 `75/75`。

框架服务题目，而不是题目服务框架。

## 八、范文规范

### 内容要求

- 开头明确项目和指标属于模拟、真实或脱敏数据；
- 项目背景能够支持所选技术；
- 架构师职责体现驱动因素、选型、约束和治理；
- 理论段回应题目，不写百科全书；
- 实践段包含问题、证据、候选、决策、实施、风险和验证；
- 效果指标使用相同测试条件和统计窗口；
- 总结回扣题目并说明不足。

### 项目实践因果链

```text
问题现象
→ 监控、日志或业务证据
→ 根因
→ 候选方案与权衡
→ 最终决策
→ 实施过程
→ 风险与副作用
→ 验证结果
```

### 模拟数据

范文使用模拟项目时必须声明：

```yaml
scenario_data: simulated
```

全文指标需与记忆卡和框架保持一致。

## 九、评价报告规范

评价仅使用内部等级：

| 等级 | 含义 |
|------|------|
| `stable` | 能迁移到新题，技术和数据经过复核 |
| `usable` | 可用于训练，仍有若干风险 |
| `revise` | 存在明显问题，需要修订 |
| `avoid` | 不建议继续使用 |

评价报告至少包含：

- 总体判断；
- 题目回应；
- 技术审查；
- 项目与指标；
- P0/P1/P2 修订清单；
- 提升到下一等级的条件。

不把内部评价换算为官方分数。

## 十、创建流程

```text
确认官方大纲或真题方向
→ 检查是否已有近义专题
→ 创建 Issue 或维护任务
→ 建立目录和元信息
→ 编写知识点
→ 编写题目驱动框架
→ 编写模拟范文
→ 提炼记忆卡
→ 技术审查和指标校验
→ 新题迁移和限时写作
→ 更新导航与当前清单
```

## 十一、完成检查单

### 结构

- [ ] 四位目录编号正确
- [ ] 核心文件存在
- [ ] 当前 README 或总导航已更新
- [ ] 相对链接有效
- [ ] 文档 ID 唯一

### 来源和数据

- [ ] 来源等级明确
- [ ] AI 内容经过人工核对
- [ ] 模拟数据明确标记
- [ ] 指标在记忆卡、框架和范文中一致
- [ ] 当前考试批次有效

### 技术

- [ ] 核心定义准确
- [ ] 候选方案比较有统一维度
- [ ] 说明限制、副作用和失败模式
- [ ] 一致性、安全、容量和恢复边界清楚
- [ ] 没有无来源的固定阈值和绝对结论

### 写作

- [ ] 题目要求逐项回应
- [ ] 理论与项目实践一一对应
- [ ] 能用纯文字完成
- [ ] 完成一次新题提纲
- [ ] 完成一次限时全文
- [ ] 评价报告未输出确定官方分数

## 十二、历史主题迁移

旧主题不必一次性重命名。迁移时：

1. 保留有价值的原始资料；
2. 新增当前 README 或当前范文导航；
3. 旧报告设置 `deprecated` 并指向新版；
4. 修正 P0 技术错误；
5. 统一记忆卡、框架和范文指标；
6. 完成后再决定是否移动到 `99-归档/`。
