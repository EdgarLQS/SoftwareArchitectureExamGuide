# 论文专题新主题文档创建规范

> 本规范适用于 `02-论文专题/` 下新增或重构论文主题。当前目录以四位数字编号为准，并区分复习资料、考场范文和来源可信度。

---

## 一、基本原则

新增主题时优先保证以下四点：

1. **结构一致**：目录和核心文件命名可预测。
2. **内容可验证**：技术结论、真题信息和考试规则有明确来源等级。
3. **考场可使用**：复习材料可以包含表格、代码和图，考场范文必须是纯文字表达。
4. **避免重复扩张**：已有主题能够覆盖时，优先补充或重构，不重复创建近义专题。

不要再以“表格数量”“篇幅越长越好”作为完成标准。完成标准应是：覆盖题目要求、技术正确、来源清楚、结构完整、能够用于限时写作。

---

## 二、目录命名

每个主题使用：

```text
四位数字编号-主题名称
```

示例：

```text
0001-软件架构风格/
0004-微服务/
0011-性能优化/
0012-事件驱动架构/
```

规则：

- 编号固定为四位数字，不再使用 `001-主题`、`005-主题` 等三位格式。
- 新编号从当前最大编号顺序递增，不因优先级变化重新编号。
- 目录名称使用考试常用术语，避免同时存在多个近义名称。
- 已有目录只在必要时重命名；重命名后必须同步修复全部链接。

---

## 三、标准目录结构

```text
02-论文专题/
  0012-{主题名称}/
    00-大纲记忆卡.md
    01-{主题名称}核心知识点.md
    02-{主题名称}论文写作框架.md
    03-{主题名称}论文范文-通用版.md
    04-{主题名称}论文评价报告.md          # 可选
    05-{主题名称}故事线.md                # 可选
    README.md                             # 文件较多时可选
```

### 必需文件

| 文件 | 用途 | 完成标准 |
|------|------|----------|
| `00-大纲记忆卡.md` | 考前快速回忆 | 一页内能恢复论文主线、关键措施和数据 |
| `01-核心知识点.md` | 技术知识库 | 定义准确、边界清楚、覆盖常考对比和适用场景 |
| `02-论文写作框架.md` | 审题与结构设计 | 能把题目要求映射到摘要和正文段落 |
| `03-论文范文-通用版.md` | 限时写作参考 | 纯文字、切题、结构完整、技术措施与问题对应 |

### 可选文件

- `04-论文评价报告.md`：用于记录评分、缺陷和修订建议。
- `05-故事线.md`：用于通过问题演进和因果链辅助记忆。
- `README.md`：专题存在多个范文、多个框架或较多扩展资料时使用。

不要为了满足目录形式创建空文件。可选文件没有实际内容时不创建。

## 四、统一元信息

新文档建议在顶部使用 YAML Front Matter：

```yaml
---
id: essay-0012-outline
title: 事件驱动架构论文写作框架
type: essay-outline
status: reviewed
priority: P1
applicable_exam: 2026-H2
source_level: reference
scenario_data: simulated
created_at: 2026-07-31
updated_at: 2026-07-31
last_verified_at: 2026-07-31
---
```

字段说明：

| 字段 | 说明 |
|------|------|
| `id` | 仓库内稳定标识，不随文件名轻易改变 |
| `type` | `knowledge`、`essay-outline`、`essay-sample`、`memory-card`、`review`、`storyline` |
| `status` | `draft`、`structured`、`reviewed`、`verified`、`deprecated`、`archived` |
| `applicable_exam` | 当前适用考试批次，如 `2026-H2` |
| `source_level` | `official`、`past_exam`、`reference`、`ai_assisted` |
| `scenario_data` | `real`、`anonymized`、`simulated`、`mixed`、`not_applicable` |
| `last_verified_at` | 最近一次核对事实和链接的日期 |

来源和场景数据的详细要求见 [`../00-项目管理/来源与数据标注规范.md`](../00-项目管理/来源与数据标注规范.md)。

## 五、文档 00：大纲记忆卡

文件名固定为：

```text
00-大纲记忆卡.md
```

建议结构：

```markdown
# {编号} {主题名称} — 论文大纲记忆卡

> 对应范文：...
> 适用题型：...
> 数据说明：本文量化数据为真实脱敏 / 模拟训练数据

## 论文脉络图
## 实践因果链
## 量化数据速记
## 考场注意事项
```

要求：

- Mermaid 主图优先使用 `graph TD`，保持单线纵向主脉络。
- 实践链使用“问题 → 原因 → 方案 → 效果”。
- 量化数据必须注明来源属性，模拟数据不得写成真实测量事实。
- 记忆数据应在同一专题所有范文中保持一致。
- 考场注意事项重点写“必须回应的题目要求”和“容易偏题的位置”。

## 六、文档 01：核心知识点

文件名建议为：

```text
01-{主题名称}核心知识点.md
```

建议结构：

```markdown
# {主题名称}核心知识点

## 一、定义与边界
## 二、核心组成或分类
## 三、工作原理
## 四、方案比较与选型
## 五、质量属性与风险
## 六、典型场景
## 七、软考答题映射
## 八、术语对照
## 九、参考来源
```

要求：

- 区分定义、特点、优势、局限和适用场景。
- 技术选型必须说明约束条件，避免写成绝对结论。
- 表格、代码、Mermaid 和 ASCII 图按理解需要使用，不设最低数量。
- 对容易变化的技术版本、考试安排和产品能力注明核验日期。
- AI 辅助内容必须人工核对后才能把状态改为 `reviewed`。

## 七、文档 02：论文写作框架

文件名建议为：

```text
02-{主题名称}论文写作框架.md
```

建议结构：

```markdown
# {主题名称}论文写作框架

## 一、适用题型
## 二、审题拆解
## 三、摘要结构
## 四、正文段落规划
## 五、技术措施与问题映射
## 六、量化指标参考
## 七、常见偏题方式
## 八、限时写作检查单
```

摘要至少覆盖：

```text
项目背景 + 个人角色 + 核心问题 + 技术方案 + 实施效果
```

正文必须确保：

- 逐项回应题目要求；
- 理论说明服务于题目，不堆砌术语；
- 每项措施包含问题、决策依据、实施方式和效果；
- 风险、局限和后续改进与前文方案一致；
- 字数分配根据当次题目调整，不固定套用单一模板。

## 八、文档 03：论文范文

推荐文件名：

```text
03-{主题名称}论文范文-通用版.md
```

若确实需要多个版本，应明确用途：

```text
03-{主题名称}论文范文-考场版.md
03-{主题名称}论文范文-技术参考版.md
```

### 考场版要求

- 采用纯文字叙述，不使用表格、代码块或 Mermaid 图。
- 角色统一为系统架构师，职责聚焦架构分析、选型、设计、治理和落地。
- 项目背景保持稳定，避免不同专题出现互相矛盾的项目规模和技术栈。
- 技术措施必须与题目中的具体问题一一对应。
- 所有量化数据应合理、前后一致，并标注为真实脱敏数据或模拟训练数据。
- 不把产品宣传指标、AI 生成数字或未经验证的统计写成官方结论。

### 技术参考版要求

- 可以使用表格、代码、配置和架构图辅助理解。
- 必须明确它不是考场直接誊写版本。
- 技术细节不能破坏论文主题主线。

## 九、来源与数据要求

所有专题至少执行以下检查：

1. 官方考试安排、考试规则和大纲信息标记为 `official`，并记录核验日期。
2. 历年题目和题干标记为 `past_exam`，注明年份和资料完整性。
3. 教材、标准和技术文档标记为 `reference`。
4. AI 生成或归纳内容标记为 `ai_assisted`，人工核对后才可进入正式范文。
5. 论文项目数据必须标记为 `real`、`anonymized`、`simulated` 或 `mixed`。
6. 没有官方答案时使用“参考答案”，不得伪称“官方标准答案”。

## 十、Markdown 与表达规范

### 标题层级

```text
# 文档标题
## 一、主要章节
### 1.1 子章节
#### 更细层级
```

### 表格

- 只在确实有比较、矩阵或结构化数据时使用。
- 表格后可增加“结论”段，但不要求每个表格机械重复一次。
- 考场版范文不使用表格。

### Mermaid

- 节点文字避免使用会破坏语法的未转义字符。
- 图必须服务于理解，不为了数量堆图。
- 修改后检查代码块是否闭合。

### 用词

- 对未经验证的数据使用“示例”“模拟”“参考”等限定词。
- 避免“必须达到”“唯一方案”“绝对不会”等缺少约束条件的表述。
- 同一术语在一个专题内保持一致，如“限界上下文”不要同时写成多个非标准名称。

## 十一、索引更新

新增或重构主题后，至少检查：

- [`README.md`](README.md)
- [`论文专题总览与故事线导航.md`](论文专题总览与故事线导航.md)
- 根目录 [`README.md`](../README.md) 中的主题覆盖表
- 当前备考计划中的资料入口
- 所有受重命名影响的相对链接

不要再更新已经不存在的 `02-论文专题.md` 或未确认存在的“真题状态表”。
