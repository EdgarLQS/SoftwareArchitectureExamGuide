# 系统架构设计师论文复习指南

> 本文是论文专题的当前入口。考试题量、题目数量、作答要求和机考规则以当次官方通知及原始题面为准；仓库中的历史统计只用于复习规划，不视为官方命题概率或评分细则。

## 一、当前训练目标

当前论文训练统一采用以下目标：

| 项目 | 训练口径 |
|------|----------|
| 作答方式 | 按当次题面选 1 题完成全文 |
| 训练时间 | 120 分钟 |
| 目标分数 | 50+ |
| 训练频率 | 每周完成 1 个提纲，每两周完成 1 篇全文 |
| 验收标准 | 连续两篇达到 50+，且题目要求均有明确回应 |

> 45 分是合格线口径，项目训练目标设置为 50+，用于给正式考试留出波动空间。

## 二、论文材料的四层结构

每个专题优先使用以下顺序复习：

```text
00-大纲记忆卡
→ 01-核心知识点
→ 02-论文写作框架
→ 03-论文范文-通用版
→ 04-评价报告 / 05-故事线（可选）
```

| 层次 | 解决的问题 | 使用方式 |
|------|------------|----------|
| 大纲记忆卡 | 考场如何快速恢复全文脉络 | 考前速记、脱稿复述 |
| 核心知识点 | 技术概念是否准确 | 查缺补漏、技术校准 |
| 写作框架 | 题目要求如何映射到段落 | 审题、列提纲 |
| 通用范文 | 如何组织成完整文章 | 限时仿写、修改 |
| 评价报告 | 哪些位置会失分 | 复盘、二次修订 |
| 故事线 | 为什么采用这些技术 | 建立因果链和记忆钩子 |

## 四、统一写作方法

论文训练采用“题目要求驱动”，不使用固定篇幅机械套写。

### 4.1 审题

1. 圈出题目要求回答的所有问题。
2. 判断题目要求的是概念说明、方法比较、方案设计还是项目实践。
3. 为每个问题分配正文位置，确保没有遗漏。
4. 明确项目背景、个人角色、核心矛盾和验收指标。

### 4.2 建议结构

```text
摘要
→ 项目背景与本人职责
→ 题目所要求的理论或方法
→ 架构选型与权衡
→ 项目实施：问题—原因—方案—效果
→ 总结、不足与改进
```

结构允许根据题目调整。完成标准不是固定段数，而是：

- 每个题目要求都有回应；
- 技术措施与业务问题对应；
- 选型有质量属性、成本和风险权衡；
- 项目效果有合理指标；
- 总结能够回扣题目。

## 五、项目背景与量化数据

论文范文中的项目规模和指标可能是训练用模拟数据。使用时必须遵守：

- 模拟数据不得描述为真实生产测量结果；
- 同一篇论文中的基线、阶段效果和最终效果必须一致；
- 指标必须能由对应技术措施合理解释；
- 不追求夸张倍数，优先保证可信、可记忆和可论证；
- 使用真实项目时应脱敏，不暴露客户、组织和敏感信息。

详细规则见[来源与数据标注规范](../00-项目管理/来源与数据标注规范.md)。

## 六、限时训练流程

### 提纲训练

```text
5 分钟审题
→ 10 分钟列摘要和正文骨架
→ 检查题目要求是否全部映射
→ 口头复述问题、方案和效果因果链
```

### 全文训练

```text
审题和提纲
→ 完成全文
→ 检查切题性
→ 检查技术正确性
→ 检查模拟数据一致性
→ 按评价报告修订一次
```

### 复盘记录

每篇论文至少记录：

- 题目和日期；
- 实际用时；
- 是否全部回应题目要求；
- 主要技术缺口；
- 结构和表达问题；
- 模拟数据是否前后一致；
- 下次需要重写的段落。
