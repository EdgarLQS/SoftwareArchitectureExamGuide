# 专题五：嵌入式、企业集成、安全与新兴技术

> 本文是当前复习版本。历史长文 [`05-辅助领域.md`](./05-辅助领域.md) 保留旧表格和例题，但其中固定分层、协议绝对化、ESB 等同 SOA、区块链天然可信等结论不再作为默认口径。

## 一、嵌入式系统与实时系统

嵌入式系统是为特定功能构建、通常受资源、功耗、时延、可靠性和环境约束的计算系统。不能只用“软硬件可裁剪”概括其全部特征。

### 1.1 实时性

| 类型 | 含义 | 示例 |
|------|------|------|
| 硬实时 | 超过截止时间可能造成系统失效或不可接受后果 | 飞控、部分工业保护 |
| 软实时 | 延迟会降低服务质量，但偶发超时仍可接受 | 多媒体、部分监控 |
| firm real-time | 超时结果失去价值，但单次超时未必造成灾难 | 某些交易和感知任务 |

实时系统关注可预测的最坏情况和截止时间，不等于“平均速度快”。设计要考虑任务优先级、调度、优先级反转、中断、共享资源和最坏执行时间。

### 1.2 可靠与安全设计

- 看门狗检测失控任务并触发受控恢复；
- 冗余可以是硬件、软件、信息或时间冗余；
- fail-safe 使故障后进入安全状态；
- fail-operational 在故障后仍维持规定功能；
- 安全性和网络安全相互影响，但目标与分析方法不同；
- 关键系统需要危险分析、故障树/FMEA、独立保护和验证证据。

“冗余越多越可靠”不成立，共因故障、相同软件缺陷、切换逻辑和复杂度都可能抵消收益。

## 二、CPS 与边缘计算

### 2.1 CPS

网络物理系统把计算、通信和物理过程闭环结合。常见分析视角包括：

```text
感知
→ 通信
→ 计算与决策
→ 控制执行
→ 物理反馈
```

这是一种理解框架，不是所有 CPS 标准唯一固定的“三层架构”。设计重点：

- 物理模型和控制周期；
- 时间同步和数据质量；
- 通信延迟、丢包和分区；
- 安全、隐私和人机协同；
- 故障降级和安全状态；
- 云、边、端的职责划分。

### 2.2 边缘计算

边缘计算把部分计算、存储和决策放在靠近数据源的位置，常用于低延迟、带宽受限、隐私和断网自治场景。它不等于替代云：

| 边缘适合 | 云端适合 |
|----------|----------|
| 实时控制、过滤、协议适配、局部推理 | 全局训练、跨站分析、长期存储和统一治理 |
| 断网缓存和本地自治 | 模型、策略和制品统一发布 |
| 降低上传带宽 | 全局对账、审计和容量弹性 |

必须设计离线队列、版本、冲突、补传、设备身份、远程升级和密钥轮换。

## 三、FACE 开放式航空电子架构

The Open Group FACE Technical Standard 通过标准化架构和接口促进航空电子软件组件可移植与复用。FACE 参考架构通常包括五个段：

1. Operating System Segment；
2. I/O Services Segment；
3. Platform-Specific Services Segment；
4. Transport Services Segment；
5. Portable Components Segment。

同时配套 FACE Data Architecture，用统一数据模型和接口描述支持组件间数据交换。

答题边界：

- FACE 不是一个具体操作系统或中间件产品；
- “可移植”需要符合相应 Profile、接口和一致性要求，不等于任意代码直接跨平台运行；
- Transport Services 提供标准通信抽象，但底层传输和平台仍需实现；
- 安全、实时性、认证和适航证据仍需项目单独完成。

## 四、ROS 2

ROS 2 是机器人软件开发框架，使用节点和中间件通信组织系统。核心概念：

| 概念 | 语义 | 适用场景 |
|------|------|----------|
| Node | 一个计算参与者，包含发布、订阅、服务等接口 | 功能模块 |
| Topic | 异步发布/订阅的数据流 | 传感器、状态和连续事件 |
| Service | 请求/响应交互 | 短时查询或命令 |
| Action | 长时间任务，支持反馈和取消 | 导航、机械臂运动 |
| Parameter | 节点配置值 | 运行参数 |

ROS 2 通常基于 DDS/RTPS 中间件，并通过 QoS 配置可靠性、历史深度、持久性、Deadline 和 Liveliness 等策略。

易错点：

- Topic 不保证所有业务场景“绝不丢消息”，行为由 QoS 和网络决定；
- Service 不适合长时间任务，否则客户端难以获得进度和取消；
- Action 也不自动提供业务幂等和安全回滚；
- ROS 2 不是固定“感知—决策—执行”三层架构，系统分层由项目设计。

## 五、IoT 与 MQTT

### 5.1 IoT 设计

常见能力：设备身份、连接、遥测、命令、设备影子、规则处理、数据存储、告警和 OTA 升级。关键问题：

- 设备身份和证书；
- 间歇连接与离线缓存；
- 命令重放、顺序和幂等；
- 固件签名、回滚和生命周期；
- 多租户、隐私和数据最小化；
- 大规模连接和主题权限。

### 5.2 MQTT

MQTT 是轻量发布/订阅协议，客户端通过 Broker 使用主题通信。

| QoS | 协议层语义 | 代价 |
|-----|------------|------|
| 0 | 至多一次传递 | 低开销，可能丢失 |
| 1 | 至少一次传递 | 可能重复，消费端需幂等 |
| 2 | 协议交换中恰好一次传递 | 交互更多、状态和延迟更高 |

QoS 2 只约束 MQTT 协议链路的交付过程，不自动保证数据库写入、设备执行或跨系统业务副作用恰好一次。仍需业务请求 ID、幂等记录、状态机和对账。

还应掌握：

- Retained Message 是主题最近保留消息，不等同历史消息队列；
- Session Expiry 影响断线后的订阅和未完成消息状态；
- Will Message 用于异常断线通知；
- 主题通配符和共享订阅需要权限与负载治理；
- TLS、客户端认证和主题级授权不能省略。

## 六、SOA 与企业集成

SOA 通过明确服务契约和可组合能力实现跨系统协同。核心元素：

```text
服务能力
+ 服务契约
+ 消费者与提供者
+ 发现/治理
+ 编排或事件协同
+ 监控和生命周期
```

### 6.1 ESB

ESB 可以提供路由、协议转换、消息转换、编排和策略执行，但它是可选集成方式，不是 SOA 定义。

ESB 风险：

- 业务逻辑集中导致变更瓶颈；
- 单一平台成为组织和运行时耦合点；
- 复杂转换缺乏测试和版本治理；
- 容量和故障域扩大。

治理原则：轻量路由、契约版本化、策略与业务逻辑分离、多副本和可观测性。现代 API Gateway、消息平台和 Service Mesh 也可承担部分集成能力，但没有一种组件自动替代完整 SOA 治理。

### 6.2 服务契约

契约至少包括：

- 输入输出和错误模型；
- 版本和兼容规则；
- 身份、授权和数据保护；
- 幂等和重试语义；
- SLO、限流和容量；
- 生命周期、废弃和迁移计划。

WSDL/SOAP 是一种实现技术，不是 SOA 的唯一形式。REST、gRPC、事件和文件交换也可实现服务协同。

## 七、搜索与 Elasticsearch

Elasticsearch 基于 Lucene 的倒排索引提供全文检索和聚合。

### 7.1 文本分析

```text
字符过滤
→ 分词
→ Token 过滤
→ 写入倒排索引
```

索引时 Analyzer 与查询时 Analyzer 应保持语义兼容。Keyword 适合精确值，Text 适合全文检索；同一字段可以使用 multi-fields 同时支持搜索和排序/聚合。

### 7.2 分片与副本

- Primary Shard 决定索引的基础分区；
- Replica 提供读取扩展和冗余；
- 分片过多会增加内存、文件句柄和集群状态成本；
- 分片过大影响迁移和恢复；
- 副本不能替代快照备份。

Elasticsearch 接近实时，不应当作所有强事务业务的主数据库。写入确认、刷新、复制和搜索可见性是不同阶段。

### 7.3 查询与聚合

- Query Context 计算相关性，Filter Context 主要做布尔过滤；
- Term 查询用于未分析精确值，Match 查询经过分析器；
- 深分页不宜持续使用大 `from + size`，可使用 `search_after` 和 PIT；
- 高基数字段聚合、脚本和前导通配符可能消耗大量资源；
- Mapping 变更和重建索引需要版本化别名和迁移方案。

## 八、系统安全

### 8.1 威胁建模

```text
识别资产和信任边界
→ 绘制数据流
→ 枚举威胁
→ 评估风险和攻击路径
→ 选择控制措施
→ 验证并持续更新
```

STRIDE、攻击树和滥用案例都是分析工具，不是简单关键词清单。

### 8.2 身份与授权

- 用户、设备、服务和运维人员需要不同身份机制；
- 身份认证后仍需资源级授权；
- 最小权限、职责分离和短期凭证；
- 密钥和证书需要生成、存储、轮换、吊销和审计；
- JWT 只是一种令牌格式，OAuth 是授权框架，OIDC 提供身份层。

### 8.3 数据保护

- 传输保护：现代 TLS、证书校验和协议降级防护；
- 存储保护：按数据分类加密并隔离密钥；
- 完整性：MAC、数字签名、哈希链或数据库约束；
- 密码：使用专用慢哈希与独立 Salt；
- 日志：避免记录 Token、密码和敏感明文。

“使用 AES/SM4 就安全”不完整，还需模式、Nonce/IV、认证标签、密钥管理和错误处理。

### 8.4 安全与可靠性

安全控制可能影响可用性和延迟；高可用机制也可能扩大攻击面。设计应同时考虑拒绝服务、故障恢复、备份、供应链和应急响应。

## 九、区块链与智能合约

### 9.1 基本组成

- 交易和状态；
- 区块及前一区块哈希引用；
- 点对点网络；
- 共识和成员管理；
- 密钥、地址和签名；
- 智能合约或链上执行环境。

区块链的“不可篡改”是经济、共识和密码学约束下的抗篡改能力，不是物理绝对不可修改。私钥泄露、共识攻击、管理员权限、合约升级和链下数据错误仍会破坏可信性。

### 9.2 公有链、联盟链和私有链

| 类型 | 成员与共识 | 主要特点 |
|------|------------|----------|
| 公有链 | 开放参与或开放验证 | 去中心化程度较高、性能和成本受共识影响 |
| 联盟链 | 已知组织共同治理 | 权限、隐私和吞吐更易控制 |
| 私有链 | 单一组织控制 | 与普通复制数据库的价值差异需论证 |

选择前必须回答：是否真的存在多方互不完全信任、是否需要共同账本、谁能写入/验证、数据能否上链以及删除和隐私要求。

### 9.3 智能合约

智能合约是按链上规则执行的程序。风险：

- 重入、访问控制、整数和精度；
- 随机数和时间依赖；
- Oracle/链下数据可信性；
- Gas/资源上限；
- 升级、暂停和密钥治理；
- 交易最终性和链重组。

合约执行确定性不等于业务正确，链上代码和链下流程都需要测试、审计和应急机制。

### 9.4 溯源

区块链只能证明“某个主体在某时提交了某数据且后续难以无痕修改”，不能证明源头数据真实。农产品、物流或证书溯源还需设备防伪、身份、审计、抽检和异常处理。

## 十、智能操作系统与 AI

可以从两个方向答题：

### 10.1 AI for OS

- 负载预测和资源调度；
- 异常检测和故障预测；
- 能耗优化；
- 安全检测；
- 运维辅助。

### 10.2 OS for AI

- GPU/NPU 和异构资源抽象；
- 模型内存、缓存和调度；
- 数据管道和设备驱动；
- 隔离、配额和多租户；
- 边缘推理和实时约束。

AI 决策需要置信度、回退策略、漂移监控和人工控制，不能直接替代确定性的安全保护机制。

## 十一、案例答题框架

### 11.1 嵌入式/IoT

```text
实时与安全目标
→ 感知、通信、计算和控制闭环
→ 协议与数据流
→ 断网、故障和降级
→ 设备身份、升级和审计
→ 时延、丢包、恢复和功耗指标
```

### 11.2 企业集成

```text
识别系统边界和服务能力
→ 定义契约和数据语义
→ 选择同步、消息或文件集成
→ 设计路由、转换和编排
→ 处理幂等、补偿和版本
→ 建立治理、SLO 和可观测性
```

### 11.3 安全题

```text
资产和信任边界
→ 威胁与攻击路径
→ 预防、检测、响应和恢复
→ 密钥、身份和权限
→ 验证证据与残余风险
```

### 11.4 区块链题

```text
说明多方协同与信任问题
→ 选择链类型和成员治理
→ 定义链上/链下数据边界
→ 设计共识、合约和隐私
→ 处理 Oracle、密钥、升级和审计
→ 说明为什么普通数据库不足
```

## 十二、考场检查

- [ ] 实时系统是否强调截止时间和可预测性而非平均速度
- [ ] FACE 是否写出五个 Segment，并避免称为具体 OS
- [ ] ROS 2 是否区分 Topic、Service 和 Action
- [ ] MQTT QoS 2 是否避免等同业务恰好一次
- [ ] SOA 是否避免等同 SOAP 或 ESB
- [ ] Elasticsearch 是否说明倒排索引、分析器、分片和近实时
- [ ] 安全是否包含身份、授权、密钥、审计和恢复
- [ ] 区块链是否说明不可篡改边界和链下数据问题
- [ ] 智能合约是否包含 Oracle、升级和密钥风险
- [ ] AI 系统是否包含置信度、回退和人工控制

## 十三、核验依据

- The Open Group FACE Technical Standard 与 FACE Reference Architecture；
- ROS 2 官方 Concepts：Node、Topic、Service、Action 和 QoS；
- OASIS MQTT Version 5.0；
- NIST Cyber-Physical Systems Framework；
- OASIS SOA Reference Model；
- Elasticsearch 官方 Mapping、Analysis、Shard 和 Search 文档；
- NISTIR 8202 Blockchain Technology Overview；
- Ethereum 官方 Smart Contract 文档；
- 当前仓库 SOA、安全、大数据和云原生专题技术校准结果。
