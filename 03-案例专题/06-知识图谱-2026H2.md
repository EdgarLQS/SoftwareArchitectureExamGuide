# 专题六：知识图谱、图数据库与 RAG

> 本文是当前复习版本。历史长文 [`06-知识图谱.md`](./06-知识图谱.md) 保留旧例题和素材，但其中 RDF/属性图混用、图查询复杂度、向量检索和 RAG 的绝对化结论不再作为默认口径。

## 一、知识图谱的定位

知识图谱通过实体、关系、属性、类型、规则和来源信息组织领域知识，使系统能够进行结构化查询、关联分析、规则推理、检索增强和可解释展示。

知识图谱不是单一数据库产品，也不等于：

- 普通关系数据库换成图数据库；
- 把文本全部转换为三元组；
- 向量数据库；
- 大语言模型的内部参数；
- 自动正确的事实集合。

一个可用知识图谱通常包含：

```text
领域目标
+ 语义模型或 Schema
+ 实体和关系数据
+ 标识、来源和版本
+ 质量约束
+ 存储、查询和推理
+ 持续更新与治理
```

## 二、两类常见图模型

### 2.1 RDF 图

RDF 使用三元组表达：

```text
subject -- predicate --> object
```

- Subject 通常是 IRI 或 Blank Node；
- Predicate 是 IRI；
- Object 可以是 IRI、Blank Node 或 Literal；
- 多个三元组构成 RDF Graph；
- Named Graph 可为一组语句增加来源、版本或上下文。

示例：

```text
<订单123> <属于客户> <客户A>
<订单123> <订单金额> "199.00"^^decimal
```

RDF 是数据模型和抽象语法，不绑定某一种存储引擎。

### 2.2 属性图

属性图通常包含：

- Node；
- Relationship/Edge；
- Label/Type；
- Node 和 Edge 上的 Properties。

适合路径、邻居、模式匹配和图算法。Cypher 等语言常用于属性图查询。

### 2.3 两者不能直接等同

| 维度 | RDF | 属性图 |
|------|-----|--------|
| 标识 | IRI、Blank Node、Literal | 节点/关系内部标识和属性 |
| 关系属性 | 通常需重ification、RDF-star 或建模节点 | 常可直接放在 Edge 上 |
| Schema/语义 | RDFS、OWL、SHACL 等生态 | Label、约束、应用 Schema |
| 查询 | SPARQL | Cypher、Gremlin、GQL 实现等 |
| 典型优势 | 语义互操作、开放数据和本体 | 工程直观、路径和属性查询 |

两种模型可以映射，但需要明确标识、关系属性、Blank Node、类型和语义损失，不能写成“格式一键无损互换”。

## 三、RDFS、OWL、SKOS 与 SHACL

### 3.1 RDFS

RDFS 提供类、子类、属性、Domain 和 Range 等基础词汇，用于描述简单 Schema 和继承关系。

### 3.2 OWL

OWL 2 用于表达更丰富的本体语义，例如：

- 类等价和互斥；
- 属性特征；
- 基数和存在限制；
- 个体相同或不同；
- 类表达式和推理规则。

OWL 通常采用开放世界假设：缺少某条事实不表示该事实为假。它也不自动采用“不同名称一定表示不同实体”的假设。

因此不能把 OWL 推理当作传统数据库中的完整性约束校验。

### 3.3 SHACL

SHACL 用 Shapes 描述 RDF Graph 的约束并生成验证结果，适合检查：

- 必填属性；
- 值类型和枚举；
- 最小/最大基数；
- 路径和关联约束；
- 自定义 SPARQL 约束。

OWL 主要描述语义和可推导知识，SHACL 主要用于数据验证；两者可以配合，但职责不同。

### 3.4 SKOS

SKOS 适合分类体系、主题词表和概念层次，提供 Concept、broader、narrower、preferred label 和 alternative label 等词汇。它不等同完整领域本体。

## 四、SPARQL 与图查询

SPARQL 用图模式匹配查询 RDF 数据，支持：

- Basic Graph Pattern；
- Filter、Optional 和 Union；
- 聚合；
- Property Path；
- Named Graph；
- Federated Query。

图数据库查询不是恒定时间。性能取决于：

- 起点选择性和索引；
- 节点度数和超级节点；
- 路径长度和分支因子；
- 查询模式和过滤条件；
- 数据分布、缓存和并行；
- 是否跨分区或跨数据源。

应避免无界可变长度路径和从超级节点开始的大范围遍历。

## 五、知识图谱构建流程

```text
明确业务问题和能力边界
→ 设计概念模型和标识策略
→ 接入结构化/半结构化/文本数据
→ 抽取实体、属性和关系
→ 实体链接、消歧和融合
→ 质量校验与人工审核
→ 存储、索引和版本发布
→ 查询、推理和应用
→ 反馈、监控和持续更新
```

### 5.1 需求与建模

先回答：

- 需要支持哪些查询、决策或解释；
- 哪些实体和关系是核心；
- 权威来源和数据负责人是谁；
- 标识是否跨系统稳定；
- 哪些信息受权限、隐私和保留周期约束；
- 需要规则推理、路径分析还是全文/向量检索。

不要先购买图数据库，再倒推业务模型。

### 5.2 信息抽取

| 任务 | 说明 | 风险 |
|------|------|------|
| 实体识别 | 找出人、组织、产品、地点等 Mention | 边界和类型错误 |
| 关系抽取 | 识别实体之间的关系 | 方向、否定和上下文错误 |
| 属性抽取 | 提取时间、金额、状态和描述 | 单位、范围和时效 |
| 事件抽取 | 识别参与者、时间和结果 | 事件角色和共指 |
| 实体链接 | 把 Mention 映射到已有实体 | 同名、别名和歧义 |

LLM 可以生成候选实体和关系，但生产入图需要：

- 结构化输出约束；
- 置信度和拒绝策略；
- 已标注评估集；
- 来源证据；
- 人工审核；
- 可撤销和回滚。

### 5.3 实体消歧与融合

常见信号：

- 唯一业务标识；
- 名称、别名和地址；
- 属性相似度；
- 关系邻域；
- 时间和来源；
- 人工确认。

融合不能只按名字相同。需要保存：

- 原始记录；
- 匹配规则和版本；
- 置信度；
- 合并/拆分历史；
- 来源和责任人。

## 六、来源、版本与时态

事实至少应关联：

```text
来源系统
+ 抽取时间
+ 业务有效时间
+ 置信度或审核状态
+ Schema/模型版本
+ 访问权限
```

同一事实可能随时间变化或不同来源冲突。不要只保存最终值而丢失证据链。

可采用 Named Graph、Statement Node、RDF-star、Edge Properties 或独立 Provenance 表表达来源，具体方式取决于图模型和查询需求。

## 七、质量治理

### 7.1 质量维度

- 准确性；
- 完整性；
- 一致性；
- 唯一性；
- 及时性；
- 可追溯性；
- Schema/Shape 符合度；
- 关系和路径合理性。

### 7.2 校验层次

```text
语法和类型
→ Schema/Shape
→ 领域规则
→ 跨来源对账
→ 人工抽样
→ 应用反馈
```

自动推理得到的新事实也应保存推理规则、输入事实和版本，便于解释和撤销。

## 八、推理、图算法和表示学习

三类能力必须区分：

### 8.1 逻辑/规则推理

根据 RDFS、OWL、规则或领域约束推导新事实。特点是语义明确和可解释，但表达能力、计算复杂度和数据质量需要控制。

### 8.2 图算法

例如：

- 最短路径；
- 连通分量；
- 中心性；
- 社区发现；
- 相似邻居。

这些算法处理图结构，不自动产生逻辑上为真的领域事实。

### 8.3 图嵌入和 GNN

把节点、关系或子图映射到向量，用于链接预测、分类和相似检索。输出是统计预测，不等于本体推理或事实证明。

应使用训练/验证/测试拆分，并防止时间泄漏、关系泄漏和负样本偏差。

## 九、向量检索

向量检索根据 Embedding 相似度返回候选内容，适合语义搜索、实体候选和文档召回。

边界：

- 相似不等于事实一致；
- 近似最近邻可能牺牲召回换取延迟；
- Embedding 模型变化会影响索引和阈值；
- 向量不直接表达来源、时态和严格约束；
- 权限过滤应在检索链路中执行，不能检索后才隐藏敏感结果。

推荐混合检索：

```text
关键词/结构化过滤
+ 向量召回
+ 图关系扩展
+ 重排序
+ 来源与权限校验
```

## 十、RAG 与 GraphRAG

### 10.1 RAG 流程

```text
问题理解
→ 查询改写
→ 文档/实体召回
→ 权限过滤
→ 重排序
→ 构造上下文
→ 模型生成
→ 引用和验证
```

RAG 把外部证据提供给生成模型，但不能自动保证答案正确。失败来源包括：

- 应召回内容未召回；
- 召回内容不相关或过期；
- 分块破坏语义；
- 模型忽略证据或错误归纳；
- 权限和来源处理错误；
- 提示注入和恶意文档。

### 10.2 GraphRAG

知识图谱可以帮助：

- 实体链接和查询消歧；
- 多跳关系扩展；
- 按类型、时间和权限过滤；
- 提供结构化证据和路径解释；
- 结合向量搜索做混合召回。

GraphRAG 也不等于“把所有图邻居放入 Prompt”。需要控制扩展深度、超级节点、Token 成本、路径质量和证据去重。

### 10.3 评估

分别评估：

| 层次 | 指标示例 |
|------|----------|
| 召回 | Recall@K、MRR、nDCG、关键证据覆盖 |
| 重排序 | 相关性、排序稳定性 |
| 生成 | 正确性、完整性、忠实度、拒答 |
| 引用 | 引用是否支持对应结论 |
| 安全 | 越权、Prompt Injection 和敏感数据泄露 |
| 运行 | P95/P99 延迟、成本和可用性 |

不能只用“用户感觉不错”或语言流畅度评价知识问答系统。

## 十一、存储与架构选型

| 需求 | 候选能力 |
|------|----------|
| 开放语义、跨组织互操作 | RDF Store + SPARQL |
| 属性丰富的路径和业务图 | Property Graph |
| 文档全文检索 | Search Engine |
| 语义相似召回 | Vector Index |
| 强事务主数据 | Relational/Transactional Store |
| 大规模离线图计算 | 分布式图处理或批处理引擎 |

实际系统可以组合多种存储，但必须明确主数据来源、同步、版本、失败恢复和一致性。不能把图数据库、搜索和向量库都视为同一份事实的无主副本。

## 十二、服务架构

```text
数据源
→ 采集与变更捕获
→ 清洗、抽取、实体链接
→ 语义模型与质量校验
→ 图/搜索/向量存储
→ 查询、推理和检索服务
→ RAG、推荐、风控和分析应用
→ 反馈、治理和重建
```

关键横向能力：身份权限、来源、版本、审计、成本、数据删除和灾难恢复。

## 十三、安全与隐私

- 图中的关系可能比单条属性更敏感；
- 路径查询和邻域扩展可能造成推断泄露；
- 权限应支持实体、属性、关系、Named Graph 或租户边界；
- 向量索引和缓存也必须执行权限过滤；
- 数据删除需要传播到图、搜索、向量、缓存和备份策略；
- Prompt Injection 文档不能直接控制系统指令；
- 对外答案保留来源、置信度和拒答机制。

## 十四、案例答题框架

### 14.1 知识图谱构建题

```text
明确业务问题
→ 设计概念模型和标识
→ 接入数据并保留来源
→ 抽取、链接和融合
→ 质量校验与人工审核
→ 选择存储和查询
→ 建立更新、版本和反馈
```

### 14.2 图数据库选型题

```text
分析数据模型和查询模式
→ 比较 RDF 与属性图
→ 评估路径、语义和互操作需求
→ 处理分区、超级节点和索引
→ 说明事务、恢复和运维
```

### 14.3 RAG 设计题

```text
定义知识源和权限
→ 设计分块、实体链接和索引
→ 混合召回与重排序
→ 上下文构造和引用
→ 防注入、拒答和事实校验
→ 分层评估召回、生成和运行指标
```

## 十五、考场检查

- [ ] 是否区分 RDF 与属性图
- [ ] 是否区分 RDFS/OWL 语义和 SHACL 数据校验
- [ ] 是否避免图查询恒定时间结论
- [ ] 实体融合是否保留来源、置信度和撤销记录
- [ ] 是否区分逻辑推理、图算法和向量预测
- [ ] 向量相似度是否避免等同事实正确
- [ ] RAG 是否说明检索、重排、引用、拒答和评估
- [ ] GraphRAG 是否控制扩展深度和超级节点
- [ ] 是否明确主数据来源和多存储同步
- [ ] 是否包含权限、隐私、删除和 Prompt Injection 防护

- W3C RDF 1.1 Concepts and Abstract Syntax；
