Redis 主从全量同步流程：

| 编号 | 标准答案 | 说明 |
|------|---------|------|
| (1) | **从库向主库发送 PSYNC -1 或 SYNC 请求** | 从库主动发起首次同步请求（PSYNC -1 表示全量复制） |
| (2) | **主库执行 BGSAVE 命令，生成 RDB 快照文件** | 主库收到请求后在后台执行 BGSAVE 生成数据快照，同时继续处理客户端写操作 |
| (3) | **主库将 BGSAVE 期间的写操作追加到 replication backlog** | 快照生成期间的增量写命令不会丢失，记录在复制积压缓冲区（backlog）中 |
| (4) | **主库通过 socket 将 RDB 文件传输给从库** | 快照生成完成后，将全量数据快照发送给从库 |
| (5) | **主库将 backlog 中积压的增量写命令发送给从库** | 从库加载完 RDB 后，主库发送 backlog 中积累的增量命令，保证数据最终一致 |

---

**扩展：BGSAVE 详细解析**（结合本题考点）

`BGSAVE`（Background Save）是 Redis 生成 **RDB 快照**的核心后台机制，也是本题主从同步流程的关键环节。

**核心概念：**
- **作用**：在后台异步生成当前 Redis 内存数据的完整快照（`.rdb` 文件），用于持久化或主从同步
- **关键特性**：**不阻塞主进程**，执行期间 Redis 仍可正常处理客户端读写请求

**底层工作原理（`fork` + COW）：**
1. Redis 主进程调用 `fork()` 创建子进程，子进程获得父进程内存空间的副本
2. **写时复制（Copy-On-Write, COW）**：fork 刚完成时父子进程共享同一块物理内存；当父进程处理写请求修改数据时，操作系统自动将被修改的内存页复制一份给子进程
3. **子进程始终看到 fork 时刻的旧数据**（保证快照一致性），**父进程继续处理新数据**（不影响业务）

**执行流程（6 步）：**
```
1. 客户端发送 BGSAVE 命令
2. Redis 主进程 fork() 生成子进程
3. 主进程继续处理客户端读写（不阻塞）
4. 子进程将内存数据写入临时 RDB 文件
   ↓ (期间主进程写操作触发 COW，子进程数据保持 fork 时刻快照)
5. 子进程写入完成，通知主进程替换旧快照
6. 主进程回收子进程资源，BGSAVE 结束
```

**BGSAVE vs SAVE（常考对比）：**

| 对比项 | `SAVE` | `BGSAVE` |
|--------|--------|----------|
| 执行方式 | 同步阻塞 | 异步后台 |
| 是否阻塞客户端 | 是 | 否 |
| 底层机制 | 主进程直接写磁盘 | fork 子进程 + COW |
| 使用场景 | 极少（仅维护窗口） | 生产环境默认 |

**在主从全量同步中的关键作用：**
- 主库收到从库 SYNC 请求后，执行 **BGSAVE** 生成 RDB 快照
- BGSAVE 执行期间，主库收到的新写命令追加到 **复制缓冲区**，不丢失
- 快照生成后，先传 RDB 文件给从库，再传缓冲区增量命令，保证最终一致

**补充答案（标准参考）：**

Redis 两种持久化方案：

**1. RDB（Redis DataBase）快照持久化：**
- **原理**：定期将 Redis 内存中的数据生成二进制快照文件（.rdb）保存到磁盘。通过 BGSAVE 命令在子进程中完成，不阻塞主进程
- **优点**：文件紧凑、恢复速度快、适合大规模数据恢复和备份
- **缺点**：两次快照之间的数据可能丢失（宕机时），不适合对数据完整性要求极高的场景

**2. AOF（Append Only File）追加日志持久化：**
- **原理**：将每个写操作以 Redis 协议格式追加到 AOF 日志文件中。支持三种 fsync 策略：always（每次写入都刷盘）、everysec（每秒刷盘）、no（由操作系统决定）
- **优点**：数据完整性高，最多丢失 1 秒数据（everysec 策略），日志追加写入性能好
- **缺点**：文件体积大、恢复速度慢、高并发写入时性能低于 RDB

**电商系统选择建议**：推荐**RDB + AOF 混合使用**。RDB 用于定期全量备份和快速恢复，AOF 保证数据完整性。如果只能选一种，高频写入场景优先选 AOF（everysec），兼顾性能和数据安全。

- 端侧AI：本地客户端部署AI大模型，部署资源扩容不是很方便

端侧AI相比云端AI的优势如下

- 端侧 可以自己进行 模型 微调 和蒸馏 
- 端侧 隐私性较高，数据安全性高

  - "自己进行模型微调和蒸馏"表述不准确——端侧资源受限，通常是在云端微调/蒸馏后部署到端侧

**补充答案（标准参考）：**

**云端 AI 定义：**
将 AI 模型部署在云端数据中心，用户通过网络（互联网）以 API 调用的方式使用模型推理和训练能力。模型运行在强大的云服务器（GPU/TPU 集群）上。

**端侧 AI 定义：**
将 AI 模型部署在终端设备（手机、PC、IoT 设备等）本地，模型推理直接在设备端完成，无需将数据发送到云端。

**端侧 AI 相比云端 AI 的优势：**
1. **数据隐私与安全**：数据不出设备本地，避免敏感数据上传云端带来的泄露风险
2. **低延迟**：推理在本地完成，无需网络传输，响应速度更快
3. **离线可用**：无网络连接时仍可正常运行，不依赖网络稳定性
4. **节省带宽和云端成本**：减少数据传输量，降低云端计算资源消耗
5. **个性化体验**：可根据本地用户数据做个性化适配
