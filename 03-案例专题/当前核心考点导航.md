## 二、统一答题骨架

### 概念与比较题

```text
给出定义
→ 列出核心组成或机制
→ 从题目指定维度比较
→ 结合题干选择方案
→ 说明限制、风险和适用场景
```

### 架构设计题

```text
识别业务目标和质量属性
→ 识别现有瓶颈
→ 给出组件、数据流和控制流
→ 说明关键技术决策
→ 处理一致性、故障、安全和扩展
→ 给出验收指标
```

### 故障与优化题

```text
现象
→ 证据和根因
→ 方案
→ 副作用和约束
→ 验证指标
```

### 图表填空题

```text
先识别图类型和层次
→ 找已知节点和数据流
→ 根据职责补空
→ 检查输入输出、方向、依赖和平衡
→ 用题干术语作答
```

## 三、缓存专题正确口径

### Cache-Aside

```text
读：查缓存
→ 未命中查数据库
→ 回填缓存

写：更新数据库并提交
→ 删除缓存
→ 通过重试、消息或延迟校验处理失败和并发问题
```

### 常见问题

| 问题 | 本质 | 常见措施 |
|------|------|----------|
| 穿透 | 查询不存在的数据绕过缓存 | 参数校验、布隆过滤器、短 TTL 空值、限流 |
| 击穿 | 热点 Key 失效时大量请求回源 | 单飞、带租约互斥重建、逻辑过期、提前刷新 |
| 雪崩 | 大量 Key 同时失效或缓存集群故障 | TTL 随机化、多级缓存、限流降级和高可用 |
| 一致性 | 数据库和缓存更新时序冲突 | 数据库提交后删除缓存、重试、版本和订阅变更 |

完整锁、复制、Cluster 和一致性边界见[Redis 当前指南](../01-知识点/03-Redis%20专题-2026H2.md)。

## 四、质量属性场景六要素

| 要素 | 需要回答的问题 |
|------|----------------|
| 刺激源 | 谁或什么产生事件 |
| 刺激 | 发生了什么 |
| 制品 | 哪个系统部分受到影响 |
| 环境 | 事件发生时系统处于什么状态 |
| 响应 | 系统采取什么动作 |
| 响应度量 | 如何量化是否满足要求 |

答题时必须使用题干中的主体、环境、组件和指标，不只背六个名词。质量属性集合不是固定六项，应根据题干和业务驱动识别。

## 五、数据库与分布式数据易错点

- BCNF 应从函数依赖和超码判断；
- 无索引查询可能锁住大量记录，但不能一律写成 InnoDB 自动升级表锁；
- 乐观并发控制仍会执行数据库更新和获取锁，不能写成“绝无死锁”；
- CAP 关注网络分区期间一致性与可用性的权衡，不是平时任意“三选二”；
- Outbox 的业务数据和事件必须在同一本地事务资源中提交；
- 图数据库多跳查询不是常数时间，关系型 Join 也不必然指数退化；
- Kappa 可以通过日志重放或有界输入处理历史数据；
- Checkpoint 不单独等于端到端 Exactly-Once。

完整说明见[数据库与分布式数据当前指南](./02-数据库与大数据分布式-2026H2.md)。

```text
D+7：完成同考点变式题

```

- 原题采分点覆盖达到 80%；
- 变式题达到 75%；
- 在完整案例中不重复同类错误；
- 能解释方案边界，而不是只背标准句。
