## 三、关键技术纠错

### 3.1 架构与评估

- 区分架构风格、模式、技术产品和质量属性战术；
- 质量属性不固定为六项；
- 4+1 视图不表示所有项目只能使用五种视图；
- ATAM 九步按业务驱动、架构方法和场景分析组织；
- SOA 不等同 ESB。

### 3.2 数据与分布式

- BCNF 使用函数依赖和超码定义；
- 无索引查询不能简化为 InnoDB 自动升级表锁；
- 乐观并发控制不等于永不加锁或永不死锁；
- CAP 描述分区期间一致性和可用性的取舍；
- Outbox 必须保持业务数据和事件同一本地事务；
- Kappa 可以通过日志重放或有界输入处理历史数据；
- Checkpoint 不单独等于端到端 Exactly-Once。

### 3.3 Web 与云原生

- 微服务不按表、代码行数或事件数量机械拆分；
- OAuth 2.0 是授权框架，OIDC 提供身份层，JWT 是 Token 格式；
- Ingress 是 API 资源，需要 Controller 实现；
- Kubernetes Secret 默认并非自动静态加密；
- Startup、Readiness 和 Liveness 探针职责不同；
- HPA 受数据库、缓存、消息和外部接口容量约束；
- Service Mesh 仍有数据面和运维成本。

### 3.4 软件工程与可靠性

- 瀑布和过程模型不使用绝对化描述；
- Scrum 使用 2020 Guide 的角色、事件和承诺；
- 维护比例和生命周期成本不再作为无来源固定数字；
- DFD 平衡使用父子边界净输入输出；
- UML 与 DFD、E-R、BPMN 分开使用；
- `MTBF/(MTBF+MTTR)` 仅在简化稳态假设下适用；
- 可靠性使用 SLI/SLO、RTO/RPO 和恢复演练验证。

### 3.5 辅助领域

- FACE 使用五个 Segment，且不是具体操作系统；
- ROS 2 区分 Topic、Service 和 Action；
- MQTT QoS 2 不自动保证业务副作用恰好一次；
- Elasticsearch 近实时、分片和全文检索语义得到校准；
- 区块链不可篡改和智能合约可信性存在密钥、共识、Oracle 和治理边界。

### 3.6 知识图谱与 RAG

- RDF、属性图、RDFS/OWL、SHACL 和 SPARQL 职责分开；
- 图查询不宣称恒定时间；
- 实体融合保留来源、置信度和撤销记录；
- 逻辑推理、图算法和向量预测分开；
- 向量相似度不等于事实正确；
- RAG 增加召回、重排、引用、拒答、安全和分层评估。
