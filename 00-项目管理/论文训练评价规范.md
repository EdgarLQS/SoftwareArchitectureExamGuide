# 论文训练评价规范

> 本规范用于评价仓库中的论文提纲和范文。所有评价均属于内部训练复盘，不代表官方阅卷结果，也不能承诺正式考试分数。

## 一、基本原则

1. **不伪造官方评分标准**：没有官方公开细则时，不自行创造“切题 20 分、实践 20 分”等精确分值并称为官方标准。
2. **不使用确定性满分**：内部检查表全部通过，只能说明符合该检查表，不能推导为 `75/75`。
3. **切题优先于模板**：题目要求是否全部回应，比固定段数、固定过渡句和字数区间更重要。
4. **技术正确优先于术语数量**：技术名词越多不代表技术深度越高。
5. **因果链优先于效果数字**：问题、原因、措施和效果必须能够相互解释。
6. **迁移能力优先于背诵完整度**：能根据新题调整结构和方案，才算真正掌握。
7. **模拟数据必须标注**：虚构项目规模和指标不能写成真实生产测量结果。

## 二、评价等级

统一使用以下四档：

| 等级 | 定义 | 使用条件 |
|------|------|----------|
| `stable` 稳定 | 能迁移到新题，技术和结构经过复核 | 连续限时训练无重大遗漏，关键事实已核对 |
| `usable` 可用 | 可作为训练材料，但仍有若干风险 | 结构完整，存在技术边界、数据或切题问题 |
| `revise` 待修订 | 存在明显问题，不宜直接背诵 | 题目遗漏、技术错误、指标冲突或来源不清 |
| `avoid` 不建议使用 | 可能传播严重错误或明显偏题 | 核心概念错误、伪造来源或无法修复的结构问题 |

可以附加内部完成度，例如“7/10 项通过”，但必须写清量表名称，不能转换为考试分数。

## 三、评价维度

### 3.1 题目回应

- 是否识别题目要求回答的所有问题；
- 每个问题是否有对应段落；
- 是否使用题目中的对象、场景和限定条件；
- 是否存在大段与题目无关的通用知识堆叠；
- 总结是否回扣题目。

### 3.2 项目背景与角色

- 项目是否能支持所选技术；
- 规模、痛点和约束是否合理；
- 系统架构师职责是否体现决策、权衡和治理；
- 是否避免把普通编码工作全部描述为架构师个人完成；
- 项目数据是否真实、脱敏或模拟标注清楚。

### 3.3 理论准确性

- 核心术语定义是否准确；
- 是否说明适用场景和限制；
- 是否避免“必须、天然、一定、零侵入、绝对一致”等无条件表述；
- 是否区分相关但不同的概念；
- 是否有来源可追溯。

### 3.4 架构决策

- 是否明确业务目标和质量属性；
- 是否比较候选方案；
- 是否说明选型依据和不选其他方案的原因；
- 是否包含成本、复杂度、安全、可用性和演进权衡；
- 是否说明失败模式和治理方式。

### 3.5 项目实践

每个重点实践建议包含：

```text
问题现象
→ 证据与根因
→ 架构决策
→ 实施措施
→ 风险与副作用
→ 验证指标
```

只写“用了 Redis/Kubernetes/Flink 后性能大幅提高”不构成完整实践。

### 3.6 数据一致性

- 同一指标在摘要、正文、记忆卡和总结中是否一致；
- 中间阶段是否出现优化后反而变差但没有解释；
- 提升幅度是否与措施和资源匹配；
- 可用性、故障频率和 MTTR 是否互相矛盾；
- 成本节省是否有容量与账单依据。

### 3.7 表达与完成度

- 结构是否清楚；
- 段落是否围绕一个中心；
- 是否存在重复结论和空泛口号；
- 是否能在规定时间内完成；
- 是否使用纯文字表达关键表格和架构图内容。

## 四、禁止作为确定评分依据的规则

以下规则可以作为个人训练偏好，但不能直接推导正式考试分数：

- 摘要必须精确为某个字数区间；
- 正文理论段必须达到固定字数；
- 必须恰好五段或十段；
- 每段必须出现“我们”；
- “我”只能出现固定次数；
- 必须使用固定数量的过渡句；
- 必须包含固定数量的问题—解决对；
- 使用某个技术名词即可获得固定分数；
- 内部检查表全部通过即为 75/75。

## 六、历史报告迁移规则

历史报告出现以下内容时，应迁移：

| 历史表述 | 迁移方式 |
|----------|----------|
| `75/75`、`100%`、`70+ 分标准` | 改为内部等级和风险说明 |
| “评审专家偏好”但无来源 | 删除或改为训练建议 |
| 固定字数即满分 | 改为完成度检查 |
| 固定“我/我们”次数 | 改为角色与团队表达是否自然 |
| 模拟数据未标注 | 增加 `scenario_data: simulated` |
| 技术方案无边界 | 增加限制、副作用和适用条件 |

迁移时保留历史改动记录，但不继续传播确定分数。

## 七、完成标准

一份论文从 `usable` 提升为 `stable`，至少满足：

```text
题目要求逐项回应
核心理论和技术边界经过复核
问题—方案—效果因果链成立
模拟数据前后一致
能够迁移到不同题目表述
连续两次限时训练无重大遗漏
```
