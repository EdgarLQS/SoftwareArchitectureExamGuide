# 来源与数据标注规范

> 本规范用于区分考试事实、历年题面、技术参考、个人训练记录、AI 辅助内容和论文模拟数据，避免不同可信度的信息在仓库中混写。

## 一、来源等级

统一使用 `source_level`：

| 值 | 含义 | 示例 | 使用要求 |
|----|------|------|----------|
| `official` | 官方机构发布 | 考试通知、大纲、官方用书目录 | 记录机构、发布日期、链接和核验日期 |
| `past_exam` | 历年题面或可追溯试卷资料 | 某年案例题、论文题目 | 记录年份、批次、来源和完整性 |
| `reference` | 教材、标准和官方技术文档 | 标准、教材、厂商文档 | 记录名称、版本和日期 |
| `personal_record` | 个人作答、成绩和训练记录 | 模拟成绩、错题回归 | 不得描述为官方成绩或普遍结论 |
| `ai_assisted` | AI 生成、改写或归纳 | 知识点总结、范文草稿 | 必须人工复核，不得单独作为事实依据 |

一个文档可以使用多类来源：

```yaml
source_level:
  - past_exam
  - personal_record
  - ai_assisted
```

## 二、文档状态

| 状态 | 含义 |
|------|------|
| `draft` | 草稿，结构和事实可能不完整 |
| `structured` | 已完成结构化整理，尚未全面复核 |
| `reviewed` | 已人工核对主要内容 |
| `verified` | 关键事实已通过官方资料、原始题面或权威来源验证 |
| `deprecated` | 已过期，不再作为当前入口 |
| `archived` | 仅作为历史资料保留 |

AI 辅助文档不能仅因格式完整而标记为 `verified`。

## 三、题面完整性

历年资料统一使用 `completeness`：

| 值 | 含义 |
|----|------|
| `complete` | 当前资料包含较完整题面和小题结构 |
| `partial` | 缺少部分题面、小题、图表或附件 |
| `image_only` | 主要内容为图片，尚未完成文本整理 |
| `reconstructed` | 根据零散资料人工整理或重构 |
| `missing` | 当前仓库没有该题内容 |
| `unverified` | 已有内容，但尚未与原始题面完成核验 |

示例：

```yaml
exam: 2024-H1
source_level:
  - past_exam
  - personal_record
completeness:
  overall: reconstructed
  verified_against_original: false
```

同一资料不得同时使用“全部占位符”和“部分完整”等互相冲突的描述。

## 四、答案来源

| 名称 | 可用表述 | 禁止误用 |
|------|----------|----------|
| 官方答案 | “官方答案” | 没有官方出处时不得使用 |
| 权威解析 | “参考某教材、机构或出版解析” | 不得简称官方答案 |
| 参考答案 | “根据题干和多来源整理的参考答案” | 不得声称唯一正确 |
| AI 辅助答案 | “AI 辅助整理，已人工复核” | 不得未经核对直接评分 |

当不同解析存在差异时，应记录分歧、采用口径和评分影响。

## 五、个人训练数据

统一增加：

```yaml
source_level:
  - personal_record
record_type: personal_practice
```

训练数据至少区分：

- 正式考试成绩；
- 90 分钟模拟考试成绩；
- 专项训练单题成绩；
- AI 或人工复评分数；
- 错题回归结果。

规则：

1. 正式成绩需要批次和成绩单来源。
2. 模拟成绩只统计明确选答的题目。
3. 额外备选题不累加进同一次 75 分成绩。
4. 评分依据变化时保留原分和复评分。
5. 资料不完整时标记训练限制。
6. 个人成绩不能用于推导命题概率或普遍难度。

## 六、论文场景数据

统一使用 `scenario_data`：

| 值 | 含义 |
|----|------|
| `real` | 可确认的真实项目数据 |
| `anonymized` | 真实项目脱敏数据 |
| `simulated` | 为训练构造的合理项目与指标 |
| `mixed` | 真实经验与模拟数字混合 |
| `not_applicable` | 文档不涉及项目数据 |

### 模拟数据声明

推荐：

> 本文项目背景和量化指标用于论文训练，属于模拟数据；重点是保持问题、方案和效果之间逻辑一致。

禁止将模拟数据描述为“生产验证结果”。

### 指标要求

- 指标与技术措施存在可解释因果关系；
- 摘要、记忆卡、框架、正文和总结使用同一基线；
- 中间阶段指标变化符合实施顺序；
- 提升幅度与资源和方案匹配；
- 可用性、故障次数和 MTTR 使用相同统计窗口；
- 成本结论有容量或账单依据；
- 模拟指标不是官方评分标准。

## 七、适用考试和时效

涉及当前考试安排、题型、报名、时间或大纲版本时，建议加入：

```yaml
applicable_exam: 2026-H2
last_verified_at: 2026-07-31
```

规则：

1. 批次统一使用 `YYYY-H1` 或 `YYYY-H2`。
2. 当前导航必须更新适用批次。
3. 历史文档保留原始创建背景，不无差别覆盖。
4. 可能变化的事实记录来源和最近核验日期。
5. 无法确认时写“以当次官方通知或原始题面为准”。

## 九、人工复核检查单

- [ ] 官方事实有机构、日期、链接和核验日期
- [ ] 历年题面标记完整性
- [ ] “官方答案”确有官方出处
- [ ] AI 辅助内容已经人工核对
- [ ] 个人成绩和正式成绩已经分离
- [ ] 论文数据标记真实、脱敏或模拟
- [ ] 同一专题中的数据保持一致
- [ ] 当前适用考试批次有效
- [ ] 可能变化的信息记录最近核验日期
- [ ] 失效来源被替换或标记过期
