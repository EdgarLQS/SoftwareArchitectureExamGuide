# 来源与数据标注规范

> 本规范用于区分考试事实、历年真题、技术参考、AI 辅助内容和论文场景数据，避免不同可信度的信息在仓库中混写。

## 一、为什么需要标注

本仓库同时包含：

- 官方考试安排和考试规则；
- 历年题目、个人作答和评分；
- 教材、标准和技术资料；
- AI 辅助归纳的知识点；
- 为论文训练设计的项目背景和量化指标。

这些内容的用途和可信度不同。没有标注时，读者容易把模拟数据当成真实项目数据，把参考答案当成官方答案，或者继续使用已经过期的考试信息。

---

## 二、来源等级

统一使用 `source_level` 字段：

| 值 | 含义 | 示例 | 使用要求 |
|----|------|------|----------|
| `official` | 官方机构发布 | 考试通知、考试大纲、官方用书目录 | 记录机构、发布日期、链接和核验日期 |
| `past_exam` | 历年真题或题面资料 | 2025 年案例题、论文题目 | 记录年份、批次和完整性状态 |
| `reference` | 权威或可信参考资料 | 教材、标准、厂商官方文档、出版解析 | 记录资料名称和版本或日期 |
| `ai_assisted` | AI 生成、改写或归纳 | AI 总结的知识点、范文草稿 | 必须人工复核，不得单独作为事实依据 |

一个文档使用多类来源时，可以写成数组：

```yaml
source_level:
  - past_exam
  - reference
  - ai_assisted
```

## 三、题面完整性

历年真题统一使用 `completeness`：

| 值 | 含义 |
|----|------|
| `complete` | 当前资料包含较完整题面和小题结构 |
| `partial` | 缺少部分题面、小题或附件 |
| `image_only` | 主要内容为图片，尚未完成文本整理 |
| `reconstructed` | 根据零散资料人工整理或重构 |
| `missing` | 当前仓库没有该题内容 |
| `unverified` | 已有内容，但没有与原始题面完成核验 |

示例：

```yaml
exam: 2024-H1
source_level: past_exam
completeness:
  overall: reconstructed
  verified_against_original: false
```

自然语言中应使用：

- “整理版，未完整核验原始题面”；
- “部分题目依赖图片引用”；
- “缺少第 3 大题”。

不要同时对同一资料使用“全部占位符”和“部分完整”等互相冲突的描述。

## 四、答案来源

案例评分中的答案统一分为：

| 名称 | 可用表述 | 禁止误用 |
|------|----------|----------|
| 官方答案 | “官方答案” | 没有官方出处时不得使用 |
| 权威解析 | “参考某教材/机构解析” | 不得简称为官方答案 |
| 参考答案 | “根据题干和多来源整理的参考答案” | 不得声称唯一正确 |
| AI 辅助答案 | “AI 辅助整理，已人工复核” | 不得未经核对直接评分 |

当不同解析存在差异时，应列出核心分歧和采用口径，而不是隐藏差异。

## 五、论文场景数据

统一使用 `scenario_data` 字段：

| 值 | 含义 | 使用场景 |
|----|------|----------|
| `real` | 可确认的真实项目数据 | 本人真实项目且允许公开 |
| `anonymized` | 真实项目脱敏数据 | 隐去客户、组织和敏感业务信息 |
| `simulated` | 为训练构造的合理数据 | 通用范文、记忆卡和模拟项目 |
| `mixed` | 真实经验与模拟数字混合 | 必须说明哪些部分经过模拟 |
| `not_applicable` | 文档不涉及项目数据 | 纯知识点或规则文档 |

### 模拟数据的写法

推荐：

> 本文项目背景和量化指标用于论文训练，属于模拟数据；重点是保持问题、方案和效果之间逻辑一致。

不推荐：

> 该项目经过生产验证，QPS 从 500 提升到 6000。

除非该数据确实来自可确认的真实项目。

### 量化指标要求

- 指标必须与技术措施存在因果关系；
- 同一专题的记忆卡、框架和范文使用一致数字；
- 数字应在合理范围内，不能只追求夸张倍数；
- 模拟指标用于帮助表达，不是官方评分标准；
- 不把厂商宣传值直接写成自己的项目效果。

## 六、适用考试和时效

涉及考试安排、题型、报名、考试时间或大纲版本时，建议加入：

```yaml
applicable_exam: 2026-H2
last_verified_at: 2026-07-31
```

规则：

1. 考试批次统一使用 `YYYY-H1` 或 `YYYY-H2`。
2. 新批次开始后，不批量覆盖历史文档中的原始时间；应区分“文档创建背景”和“当前适用批次”。
3. 作为当前导航入口的文档必须更新适用批次。
4. 可能变化的事实需要附核验日期。
5. 无法确认当前规则时使用“以当次官方通知或原始题面为准”。

## 七、推荐元信息模板

### 知识点文档

```yaml
---
id: knowledge-cache-001
type: knowledge
status: reviewed
applicable_exam: 2026-H2
source_level:
  - reference
  - ai_assisted
scenario_data: not_applicable
updated_at: 2026-07-31
last_verified_at: 2026-07-31
---
```

### 历年真题文档

```yaml
---
id: case-2025-h2
type: past-exam
status: structured
exam: 2025-H2
source_level: past_exam
completeness:
  overall: complete
  verified_against_original: true
scenario_data: not_applicable
---
```

### 论文范文

```yaml
---
id: essay-performance-sample
 type: essay-sample
status: reviewed
applicable_exam: 2026-H2
source_level:
  - reference
  - ai_assisted
scenario_data: simulated
updated_at: 2026-07-31
---
```

> 注意：实际使用时删除 `type` 前多余空格，保持 YAML 对齐。示例强调字段含义，不作为自动化解析测试文件。

---

## 八、人工复核检查单

- [ ] 官方事实是否有机构、日期和链接
- [ ] 历年题面是否标记完整性
- [ ] “官方答案”是否确有官方出处
- [ ] AI 辅助内容是否已经人工核对
- [ ] 论文数据是否标记真实、脱敏或模拟
- [ ] 同一专题中的数据是否一致
- [ ] 文档适用考试批次是否仍有效
- [ ] 可能变化的信息是否记录最近核验日期
- [ ] 失效来源是否替换或标记过期
